### 2. Sprint 0.3 要新增的 Tools（仅 2 个 Prism 自定义）

不新增「写代码」类 tool——写脚本继续用 OpenCode 内置 **`edit` / `write`**（与 LaTeX 改 `.tex` 相同）。

| Tool | 谁可调用 | 职责 | 与内置 tool 的关系 |
|------|----------|------|-------------------|
| **`experiment-log`** | **仅 orchestrator**（主 session） | 实验岛 CRUD + 读 log + 环境探测 + 手动 append run | 替代对 `meta.json` / `runs.jsonl` 的 generic `read`/`write` |
| **`experiment-run`** | **仅 orchestrator** | 在指定实验岛内：**detect_env → bash → append JSONL** 一步完成 | 内部复用现有 **bash PTY bridge**；对外是「跑 + 记」wrapper |
| `read` / `edit` / `write` | orchestrator | 写 `<experiment-dir>/<slug>/scripts/*.py` 等 | 已有，**不加**新 tool |
| `bash` | orchestrator | 建 venv、`pip install`、或 **非实验** shell | 实验岛**内执行主逻辑**应优先 `experiment-run`；裸 bash 后 module 要求补 log |
| `research-brief-read` | orchestrator | 读 brief，供 create 时填 `briefLinks` | Sprint 0.2，0.3 workflow 前置 |
| Task | orchestrator | 委派 **methodology-auditor** 等 | auditor **不**调 experiment tools |

#### `experiment-log` — action 一览

单 tool、多 action（避免 brief 那样拆两个 read/update 文件过多；run 单独 wrapper）。

| action | 何时用 | 主要返回 |
|--------|--------|----------|
| `list` | 用户问「有哪些实验」 | 实验 id 列表 + runCount |
| `create` | 新开一座实验岛 | `{ id, path, meta }` |
| `read` | 审计前、续跑前、回复用户 | `{ meta, runs[] }` |
| `append_run` | 裸 bash 后的兜底 / 手动补记 | `{ ok, run }` |
| `detect_env` | create 后或 run 前单独探测 | `{ env }` |

`tools/index.ts` 中为该 tool 写 **usageHint + workflowRules**（与 `research-brief-read` 同级），例如：

- 禁止 generic `read`/`write` 直接改 `runs.jsonl` / `meta.json`
- 无 experiment 文件夹时不得在其他目录建实验结构

#### `experiment-run` — 参数与行为

| 参数 | 说明 |
|------|------|
| `id` | 实验 slug |
| `command` | 在实验岛 cwd 执行的 shell 命令 |
| `artifacts?` | 预期产出相对路径（写入 run 记录） |
| `notes?` | Agent 可选注释 |

固定流水线：`resolve path` → `detect_env` → `bash bridge` → `append_run` → 返回 `{ exitCode, stdoutTail, stderrTail, run }`。

**权限组：** `shell`（与 `bash` 相同，走 command confirm UX）。

### 6. 端到端 Workflow 示例（orchestrator 视角）

用户：「按 brief 里的 H1 跑一个 lr ablation，并检查方法有没有问题。」

```text
1. [proactive-scheduling] 判断需要：brief + experiment + 可能 auditor

2. research-brief-read
   → 得到 Hypotheses / claims 节

3. experiment-log  action=list
   → 确认 experiment 文件夹已配置；无则报错 hint

4. experiment-log  action=create  title="LR ablation"  briefLinks={...}
   → experiment/exp-20260707-lr-ablation-a3f2/

5. edit  →  experiment/.../scripts/train.py

6. bash（可选一次）→  python -m venv .venv && .venv/bin/pip install torch ...
   → 若此 bash 是「安装依赖」而非「主实验 run」，可 append_run 记为 setup run，或 notes 区分

7. experiment-run  id=exp-...  command=".venv/bin/python scripts/train.py --lr 0.001"
   → runs.jsonl +1；返回 exitCode、env、artifacts

8. Task → methodology-auditor
   sub-prompt 含：brief H1 摘录 + meta.json + 最近 runs JSON（不是让 auditor 调 tool）

9. 综合 auditor risk list + run 结果 → 回复用户
   （若需写回 brief Open questions → research-brief-update，属 research-design 链）
```

## 关键前提：Workspace Experiment 目录（必读）

Prism 已在 **Settings → Workspace** 支持按职能配置顶层目录（`manuscript` / `experiment` / `literature` / `notebook` / `custom`），持久化于：

```text
.prismnext/settings.json  →  workspaceDirs[]
```

**默认 scaffold 只有 `manuscript` + `notebook`，不包含 `experiment`。** 因此：

| 情况 | Agent 行为 |
|------|------------|
| 已配置 `function: "experiment"` | 所有实验岛创建在 `<projectRoot>/<name>/` 下 |
| **未配置** | `experiment-log` / `experiment-run` 返回 `{ ok: false, error: "no_experiment_folder", hint: "..." }`；**module 禁止**在 manuscript / 随意路径创建实验 registry |
| 用户自定义目录名 | 尊重配置（如 `analysis/`、`exp/`），tool 返回 **resolved 相对路径** |

实现需新增 shared helper（与 `findManuscriptConfig` 对称）：

```typescript
// src/renderer/types/workspace.ts (+ main re-export)
findExperimentConfig(dirs): { dir: string } | null
resolveExperimentDir(projectRoot, prismDir): { rel: string; abs: string } | { error: "not_configured" }
```

`workspace-folders` module（全局）应补充一句：若列表中 **无 Experiment 文件夹**，实验类 workflow 需先请用户在 Workspace 中添加。

## 实验岛目录结构

假设 Workspace 配置 `experiment` → 目录名 `experiment/`：

```text
experiment/                          ← Workspace 配置的 experiment 职能根（用户可改名）
└── exp-20260707-h1-a3f2/            ← 自动 slug（一次实验 = 一座岛）
    ├── meta.json                    ← 标题、创建时间、briefLinks、tags
    ├── runs.jsonl                   ← 每次运行一行 JSON（append-only）
    ├── scripts/                     ← Agent 写的 .py / .R / .sh 等
    ├── results/                     ← 图表、csv、模型权重等 artifact
    └── .venv/                       ← Python 虚拟环境（可选；**必须在岛内**，不污染项目根）
```

原则：

- **一座岛 = 一个实验主题**（通常对应 brief 中一条 hypothesis 或一个 research question 子问题）。
- **Python 环境**默认在 `<slug>/.venv/`；Agent 用 `bash` 在岛内 `python -m venv .venv && source .venv/bin/activate && pip install ...`。
- **禁止**把 venv 建在项目根或 manuscript 目录（module binding）。

## Slug 规则（自动 ID）

格式：`exp-YYYYMMDD-<slug-base>-<shortid>`

| 部分 | 规则 |
|------|------|
| 前缀 | 固定 `exp-` |
| 日期 | UTC `YYYYMMDD` |
| slug-base | 来自 `title` 或 brief hypothesis 的 kebab-case，最长 24 字符，小写 `[a-z0-9-]` |
| shortid | 4 位 hex（随机），避免碰撞 |

示例：`exp-20260707-lr-ablation-a3f2`

创建时若碰撞，递增 shortid 重试。

## Brief ↔ 实验关联

`meta.json` 示例：

```json
{
  "id": "exp-20260707-lr-ablation-a3f2",
  "title": "Learning rate ablation on baseline",
  "createdAt": "2026-07-07T14:30:00.000Z",
  "briefLinks": {
    "sections": ["Hypotheses / claims", "Research question"],
    "hypothesisExcerpt": "H1: LR=1e-3 outperforms 1e-4 on validation loss",
    "researchQuestionExcerpt": "Does LR affect convergence speed?"
  },
  "tags": ["ablation", "baseline"]
}
```

Workflow（module binding）：

1. `research-brief-read` → 确认要验证的 hypothesis / question  
2. `experiment-log` `create` → 写入 `meta.json`（含 `briefLinks`）  
3. 在 `<slug>/scripts/` 写代码 → **`experiment-run`** 执行并 log  
4. 必要时 `methodology-auditor` Task：prompt 内带 **runs 摘要 + meta + brief 摘录**

不在 brief.md 内反向写入 experiment id（P1 可选：brief 的 Open questions 节手动/Agent 更新链接）。

## JSONL vs Markdown（Run 记录）

| 格式 | 用途 |
|------|------|
| **`runs.jsonl`（P0 主存储）** | 每行一条 run；tool 返回可解析数组；chat widget 可渲染表格/卡片；`methodology-auditor` 易筛选 |
| `README.md`（P1 可选） | 人类可读摘要；非 agent 主路径 |
| brief 式 Markdown log | ❌ 不采用 — 不利于结构化 append 与 widget |

## bash 与 log 绑定：Module 不够，需要 wrapper

| 方式 | 评价 |
|------|------|
| 仅 module「跑完记得 log」 | ❌ 易漏记、exit/artifact 不一致 |
| Agent 手动 `bash` 再 `experiment-log append_run` | 🟡 可行但两步、易忘 env 快照 |
| **`experiment-run` wrapper（P0）** | ✅ 一次调用：env 探测 → bash → 解析 exit → append JSONL → 结构化返回 |

`experiment-run` **不替代** `bash` 通用能力；仅在 **已创建的实验岛** 内使用。通用 shell 仍走 `bash` tool，但 module 要求：若在 experiment 岛内执行了裸 `bash`，**下一 tool 必须是 `experiment-log append_run`**（兜底纪律）。

## 环境检测（P0）

在 `experiment-run` 开始时（及 `experiment-log` `detect_env` action）采集：

| 字段 | 来源 |
|------|------|
| `python` / `pythonVersion` | `which python3` + `python3 --version`（优先岛内 `.venv/bin/python`） |
| `R` / `Rscript` | `which Rscript`（若存在） |
| `platform` | `process.platform` |
| `gitCommit` | `git rev-parse --short HEAD`（失败则 null） |
| `venvPath` | 相对实验岛：`.venv` 是否存在 |

## Tool 契约

### `experiment-log`

**Args:** `action` — `list` | `create` | `read` | `append_run` | `detect_env`

| action | 主要参数 | 返回 |
|--------|----------|------|
| `list` | — | `{ experimentRoot, experiments: [{ id, title, runCount, lastRunAt }] }` |
| `create` | `title`, `briefLinks?`, `tags?` | `{ ok, id, path, meta }` |
| `read` | `id`, `runsLimit?`（默认 20） | `{ meta, runs[], experimentRoot }` |
| `append_run` | `id`, `run`（部分字段；runId/时间戳可自动生成） | `{ ok, run, path }` |
| `detect_env` | `id` | `{ env, experimentPath }` |

**未配置 experiment 文件夹时：** 所有 action 返回 `{ ok: false, error: "no_experiment_folder", hint: "Add an Experiment folder in Settings → Workspace." }`

### `experiment-run`

**Args:** `id`, `command`, `artifacts?`（预期输出相对路径）, `notes?`

**行为：**

1. Resolve 实验岛路径  
2. `detect_env`  
3. 经现有 bash bridge 在实验岛 cwd 执行 `command`  
4. Append `runs.jsonl`  
5. 返回 `{ ok, run, stdoutTail, stderrTail, exitCode }`

**权限：** `shell` 组（与 `bash` 相同 confirm UX）

## Module `experiments` 要点

- 任何 **实验 / 分析 / 跑脚本 / 验证 hypothesis** 请求 → 先确认 Workspace 有 experiment 目录（tool list 或 workspace-folders）  
- 无 experiment 目录 → **引导用户** Settings → Workspace → Add folder → function **Experiment**  
- 创建实验前 → 建议 `research-brief-read`，`create` 时填 `briefLinks`  
- **优先 `experiment-run`**，避免裸 `bash` 不落 log  
- 代码写入 **仅** `<experiment-root>/<slug>/scripts/`（及岛内 `results/`）  
- Python venv **仅** `<slug>/.venv/`  
- Task `methodology-auditor`：orchestrator 提供 **meta + recent runs + brief 摘录**；auditor 不直接写 log  
- 与 `research-design` module 衔接：design 冻结后再开新 `create`
