## Tool 契约

### `latex-root`

**Args:** `mainFile?` — 可选相对路径；缺省则自动解析。

**Returns (JSON):**

```json
{
  "mainFile": "manuscript/main.tex",
  "absolutePath": "/proj/manuscript/main.tex",
  "engine": "xelatex",
  "bibTool": "biber",
  "buildDir": ".prismnext/compile",
  "manuscriptFolder": "manuscript",
  "resolution": "workspace-config | magic-root | documentclass | main.tex-fallback"
}
```

### `latex-compile`

**Args:** `mainFile?`, `useTexlive?` (default false)

**Returns:**

```json
{
  "success": true,
  "mainFile": "manuscript/main.tex",
  "buildDir": ".prismnext/compile",
  "pdfPath": ".prismnext/compile/main.pdf",
  "errors": [],
  "errorSummary": "",
  "logTail": "..."
}
```

失败时 `success: false`, `errors` 为结构化条目 `{ file, line, message }`（从 log 解析，至少保留 `errorSummary`）。

### `latex-bib-check`

**Args:** `bibPath?` — 缺省 `findProjectBibPath` + 扫描 `\addbibresource`/`\bibliography`

**Returns:**

```json
{
  "texFilesScanned": 3,
  "bibPath": "references.bib",
  "citeKeysInTex": ["foo", "bar"],
  "keysInBib": ["foo", "baz"],
  "missingKeys": ["bar"],
  "unusedKeys": ["baz"],
  "duplicateKeys": []
}
```

可选 `libraryCheck` 字段：若文献库有 paper 但 tex 未引用（复用 `citeCheckLiterature` 逻辑）。

## 用户体验验证

### 前置条件

1. **重启 dev 或生产构建** — `pnpm dev` 或重新打开打包 app，确保 main 进程启动 `startLatexBridge()`。
2. **新开 Chat tab** — OpenCode 工具列表 largely session-scoped；旧 tab 可能看不到 `latex-*`。
3. **打开 LaTeX 项目** — 含 `main.tex` 或 workspace 配置的 `mainTex`；`.bib` 与 `\cite`/`\citep` 引用存在更佳。
4. **Orchestrator** — 使用 `research-prism`（或已挂载 `latex-workspace` module 的 profile），以便 Agent 知道 compile 链。

### 场景 A — 完整写作闭环（主验收）

在 **新 chat tab** 发送类似 prompt：

```text
请用 latex-root 查主文件，然后 latex-compile 编译，最后用 latex-bib-check 检查引用。
如有 missing keys 请告诉我。
```

**期望：**

| 步骤 | 用户可见 | 通过标准 |
|------|----------|----------|
| `latex-root` | Chat 出现 tool call + **LaTeX root** widget | 显示 `mainFile`、`engine`、`bibTool`、`buildDir` |
| Agent 编辑 | Proposed Changes 或 inline edit（若你要求改 tex） | 可选；验收可跳过 |
| `latex-compile` | **LaTeX compile** widget | 成功：绿色/成功态 + `pdfPath`；失败：errors / errorSummary 可读 |
| `latex-bib-check` | **Bib check** widget | 列出 `missingKeys` / `unusedKeys` / `duplicateKeys` |

**无需**用户点击 Preview 的 Compile 按钮或 `/compile`。

### 场景 B — 编译失败诊断

故意在 `.tex` 留语法错误，再让 Agent `latex-compile`。

**期望：** widget 或 tool 输出含 `success: false`、`errors[]` 或 `errorSummary`；Agent 能根据摘要建议修复。

### 场景 C — Bib 不一致

在 `.tex` 引用 `\cite{notInBib}`，`.bib` 留 `\unusedEntry` 未引用。

**期望：** `latex-bib-check` 的 `missingKeys` 含 `notInBib`，`unusedKeys` 含 `unusedEntry`。

### 场景 D — 与 UI 编译对照（回归）

1. 同一项目用 **UI Compile**（Cmd+Enter）成功。
2. 同一项目用 Agent **`latex-compile`** 成功。
3. PDF 出现在 `.prismnext/compile/`；Preview 面板可刷新查看。

两者应一致（同一 `compileLatex` 路径）。

### 场景 E — 权限

三个 latex tool 为 **READ_ONLY**，首次调用不应弹出 write 权限门；若出现 permission 面板，属 bug。
