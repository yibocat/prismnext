# Sprint 0.2 — Research Brief Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Agent 与 orchestrator 能读写项目内 **research brief**（`.prismnext/research/brief.md`），`research-design-coach` Task 可基于 brief 而非纯口述。

**Status:** ✅ **Completed** — 2026-07-07

**Architecture:** 沿用 literature / latex 的 **file-bridge** 模式；brief 正文 **不预注入 system prompt**，由 agent 按需调用 `research-brief-read` / `research-brief-update`。文件 scaffold 在 **打开项目**（`project:ensure`）与 **read/ensure IPC** 时 idempotent 创建。

**Parent specs:** `docs/superpowers/specs/⭐️2026-07-04-platform-capabilities-phase0-backlog.md` § Sprint 0.2

## Brief 何时进入 Agent 上下文？（重要）

**Brief 不会自动注入 system prompt 或每轮 user prompt。**

| 机制 | 是否注入 brief 正文 |
|------|---------------------|
| `_prism-system.md` / core-persona | ❌ |
| Orchestrator `agent.md` | ❌（仅 module 文字说明路径与 workflow） |
| Module `research-design` | ❌（binding 规则，非文件内容） |
| **`research-brief-read` tool** | ✅ **唯一常规路径** — agent 主动调用后正文进入 tool result |
| **`research-brief-update` tool** | ✅ 写入磁盘；返回 JSON 确认 |
| 用户 `/brief` 命令 | ❌ 不注入正文 — 模板指示 agent **去调 read tool** |
| Settings UI 编辑 | ❌ 与 agent 无关，直接写文件 |

与 **Skills** 类似：Module 告诉 agent「什么时候、用什么 tool」；**正文在 tool 调用后才进 context**。

## 文件最初如何生成？

**不依赖用户先跑 `/brief`。** 默认路径：

1. **打开项目** → renderer `document-store` 调 `project:ensure` → main `ensureResearchBrief()`  
   - 若不存在：写入 `RESEARCH_BRIEF_TEMPLATE`  
   - 若已存在：**永不覆盖**

2. **Agent 首次 `research-brief-read`** → bridge `read` + `{ ensure: true }` → 同上（缺则建）

3. **Settings → Edit brief** → `researchBrief:ensure` → 同上

4. **`/brief` 命令** → action `ensure-research-brief` → 同上（并给用户一条 status 反馈）  
   - **不是**创建 brief 的唯一方式；是显式「确保存在 + 启动 AI brief 工作流」的快捷入口

## Tool 契约

### `research-brief-read`

**Args:** 无

**Returns:** `{ path, exists, raw, sections: { "Research question": "...", ... }, sectionNames, lastModified }`  
缺文件时 `ensure` 后返回模板内容。

### `research-brief-update`

**Args:** `section`（canonical 节名）, `content`, `append?`（默认 replace）

**Returns:** `{ ok, section, append, path, lastModified, error? }`

---

## Module `research-design` 要点

- 研究问题 / 假设 / 贡献 / scope → **先 read**
- **禁止** Task 子代理 read/write brief
- Task `research-design-coach`：**prompt 内带 brief 快照**；coach 只诊断，orchestrator update

| 类型 | 行为 |

| **AI template** | 指示 agent：`research-brief-read` → 按 `$ARGUMENTS` 维护 brief → 确认后 `research-brief-update` |

用户输入 `/brief` 或 `/brief 帮我把假设写清楚` 均可。

## 用户体验验证（手动）

### 1. Scaffold（无需 /brief）

1. 打开（或新建）项目  
2. 检查 `.prismnext/research/brief.md` 存在且为模板  

### 2. UI

Settings → Prompts & Rules → **Edit brief** → 编辑 Research question → 保存 → 文件已更新  

### 3. Agent read

新 chat tab：「读一下 research brief」→ 出现 `research-brief-read` → 回复含 brief 内容  

### 4. Agent update

「把 Research question 更新为：……」→ `research-brief-update` → 文件仅该节变化  

### 5. `/brief`

聊天输入 `/brief` → status：Created/Loaded → agent 调 read 并引导填写空节  

### 6. Coach 链路

「读 brief，委派 research-design-coach 压测，把开放问题写回 Open questions」→ read → Task → update
