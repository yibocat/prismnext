# Changelog — 0.8.x series

> **Detailed dev log** for this line. GitHub Release uses the summarized copy in [`../releases/`](../releases/) (regenerate with `pnpm release:changelog 0.8.0` before tagging).

## 0.8.0 (Unreleased)

### Chat

- Left sidebar session rows now use a unified status model: waiting, running, unread, and read each get their own mark. A running chat pulses a small dot (or a corner blink on a custom icon). Worktree chats still show the workflow icon when idle. Unread is stored in app settings; opening a chat clears it. If an agent turn or AI terminal finishes while you are in another chat, that row is marked unread (and slightly bolder). A pending question on an open tab counts as waiting.
- Right-click a chat in the left sidebar to Pin, Rename (inline, same as the hover card), Edit icon (emoji or Lucide, same compact picker as Teams — no image, no category headers; color tints Lucide only), Mark unread / read, Archive, or Copy (session ID, git branch, or a plain-text markdown transcript). Hover trailing is pin, archive, then a compact time (`11m`, no “ago”) — the slots stay reserved so the row does not jump. A pinned chat uses a filled pin in the same color as the title. The Pinned heading stays on the left. Delete stays on archived rows only.
- Session and team icon pickers share one compact grid: more emoji and Lucide icons, no category labels or extra rules, a search field for icons, and a wider Lucide tint row (theme colors plus a few fixed hues). Clicking empty space once dismisses the session icon submenu and the parent menu together, without synthesizing Escape (that loop froze the app). Choosing a Lucide tint writes that pick once — a leftover draft color no longer overwrites it.
- New and Default chat backgrounds are paper planes. Theme packs no longer swap in their own watermark on first launch.
- Worktree in the composer bar uses the same node/workflow icon as the Git panel, not the branch glyph. Close / Merge labels follow the app language.
- Choosing a Git branch in AI Chat now checks it out, like the Git panel. The composer footer and the Files tree follow that checkout instead of a leftover “next” mark that never ran.



### Agent

- OpenCode Go / Zen models that only appear after a live catalog refresh (for example `deepseek-v4-flash-vision-exp`) no longer fail at send with `unknown_pi_model` — chat now refreshes the provider catalog with your API key before resolving the Pi session model, matching Settings → Fetch models.
- `figure-tikz` now appears in the session skill list. Pi parses `SKILL.md` as real YAML; an unquoted `Closed path: match` is a nested mapping, so the loader dropped that skill. Other skills stay unquoted and use `—` instead of `:` .
- A provider 500 (empty reply, no thinking) is no longer treated as a finished turn. The chat now shows the error, the main log records `turn.fail`, and an empty first reply does not trigger an automatic session title.
- A silent turn (no model events for 3 minutes) still stops, but aborting Pi no longer overwrites that with a generic “could not start this turn”. The chat shows the timeout or “stopped before the model finished”. Thinking timers freeze when a tool or reply starts, so they do not keep counting through the rest of the turn. A leftover rollback banner does not pop back when a later turn fails.

Left-nav, shortcuts, and the command palette no longer pass unused `react-resizable-panels` handles. Call `leaveRightAreaMaximize()` / `applyShellWindowLayout` instead.

- Type-checking now uses TypeScript 7 (native compiler). `pnpm typecheck` is the same command and should finish faster; running and packaging the app still go through Vite.
- Desktop build toolchain moved to Vite 7 and electron-vite 5 (React plugin 5). Vite 8 waits until electron-vite supports it. Node type definitions now follow Electron 43’s Node 24.
- Chat store file slices (`stores/chat/`) again pass `pnpm typecheck` after Phase 4 split — missing imports and composer mention types only; runtime behavior unchanged.
- Changelog split into **`changelog/series/`** (detailed dev log) and **`changelog/releases/`** (GitHub Release summaries). Regenerate release notes with `pnpm release:changelog X.Y.Z` before tagging; CI reads `releases/` first.

### Shell

- Shortcut chips on New Agent, left-nav workspace modules, the empty RightArea launcher, and the RightArea + menu stay hidden until you hover (or focus / highlight) the row.
- Folding or unfolding the left sidebar no longer plays RightArea’s open motion. Center (or a maximized Right) eases with the left rail so an already-open RightArea stays put.
- The title-bar status dot hover now lists Git (branch + dirty count) and an app update when one is waiting. The outer dot is still Agent health.
- RightArea maximize / fold hover and selected fills line up with the icons. Column widths now leave room for the 1px sashes, so the window-edge paint layer and the title-bar hit fills share one right edge. Clicking maximize no longer collapses that sash to 0 (that 1px jump).
- The title-bar New Chat + no longer turns into a solid hover block: the status-dot overlay only reserves width and does not steal that hit target. The status dot sits on the same title-bar centerline as the icons.
- Dragging RightArea no longer stops at the remembered 1100px cap. That number is only the saved split width. The sash can keep going until Content is 400px, then another 140px maximizes. Clicking maximize now eases both columns by width (not flex leftover), so the 220ms motion works again.
- Unused leftover TitleBar / MainToolbar files are gone. Window chrome stays on the per-column title bars and pinned clusters.
- Settings detail width now persists on sash release (`settingsDetailWidth`), so the pane no longer springs back to the workspace RightArea width. Closing Settings detail uses the Settings close path; leaving Settings for Templates or Teams no longer flashes the workspace RightArea. Narrow windows stack the detail without rewriting the remembered width.
- Dragging RightArea wider now sticks Content at 400px, then another 140px of travel maximizes the panel — the old ~50% / main-minus-400 ceiling is gone. Releasing the sash keeps that maximize. Opening and keeping a split still share the same 680px floor (400 + 280); the extra 40px margin is gone. Title-bar fold buttons follow the live column, not a leftover store flag.
- Desktop glass is the left sidebar only, using Electron 43’s `setVibrancy("sidebar")` / Windows `mica`. Title bars stay opaque with the workspace so they do not float as a glass strip over chat and the editor. Turning it off now actually strips native vibrancy (`null` / `none`) and paints a solid window fill. The old Electron 35 “always-transparent window + punch holes in every surface” path is gone.
- Dragging the left sidebar closed no longer makes the traffic-light / sidebar buttons vanish before you release. The live CSS mark now shows the title-bar cluster; the store still commits on pointer-up so the sash does not remount mid-gesture.
- Opening the app with glass already on no longer turns native vibrancy off (renderer default) and back on after settings load. The workspace column stays an opaque fill while Library maximizes, so the transparent body does not flash the desktop through the gap.
- Clicking the left sidebar toggle (or its shortcut) now eases the panel open and closed. The toggle and search buttons stay put; New Chat and the status dot ease in beside them. Clicks go to real title-bar buttons (Electron only treats `no-drag` on descendants of the window-move region); hover fills paint on that same layer so they still highlight. The sidebar keeps its pixel width (280–520) and slides away as a slab instead of squashing with the window. Dragging the sash is still immediate. Reduced-motion settings skip the animation.
- The first drag that closes the left sidebar can be pulled open again without releasing. Title bars stay window-move regions; a leftover `.no-drag` rule had punched out Content and RightArea chrome.
- The left sidebar resize line is easier to grab (wider hit, same as the library target) and lights up on hover like the RightArea sash. The center↔RightArea line is unchanged so the chat rail stays clickable.
- Hovering a chat row keeps the pin on the status mark (same 14px cell). A Hint wrapper had been taking the pin out of that cell.
- Right-click the left sidebar to customize which **workspace modules** appear and in what order. The list is the RightArea plugin set. Default Nav is TeX Workspace and Library; other modules (and later ones) start hidden. New Chat, Templates, and Teams sit above a divider and are not customizable. Settings stays in the footer. Shortcuts still open a hidden module. Reorder uses the same whole-row drag and insert line as workbench projects.
- Tooltips wait 700ms on first hover (then nearby icons can appear sooner). Opening a dialog or panel no longer auto-focuses an icon button, so a hint does not pop the instant the surface appears. Tabbing to a control still shows the hint.
- RightArea shortcuts: ⌥⌘B opens or closes the split panel; ⌃⌘B opens or closes a maximized RightArea (it does not drop back to split). Both ease over 220ms like the left sidebar. The fold button stays pinned to the window corner; maximize eases in beside it. The + that opens a mode stays immediately left of the tabs, not in that window-corner cluster. The title-bar status dot stays in its slot instead of riding the maximize slide. Dragging the sash stays immediate.
- The app shell no longer uses percentage flex panels for Left / Content / Right. Widths are pixels: Content shrinks first, then both rails ease toward 280, then a too-narrow window snap-closes split Right (it stays closed) and folds Left. A window-folded Left comes back at 280 only. User-folded Left stays folded. The sash still sticks at 280, then another 140px of travel collapses the rail to 0 — the same detent opens it. Click and shortcut toggles still ease 220ms; sash and window stay instant. Title-bar spacers follow the same pixel columns. Settings uses the same Left water-fill; its list/detail split is unchanged. Editor WorkspaceSplit is unchanged.
- Window resize and sash release are no longer one path. Dragging a sash is 1:1 (Left 520, Right any remembered width). The window then water-fills from those remembered pixels: Content keeps 400, then the rails ease toward 280. The window width is `innerWidth` / the viewport, not `#main-layout`.
- Opening split RightArea uses the remembered pixel width (default 500). The sash is 1:1. Center is the leftover column so toggling the left sidebar does not ease RightArea along with it. Shrinking the window still keeps 400px of Content, then yields the rails.



### Architecture

- Renderer stores must not import modes or components. Literature formatting, chat-turn helpers, experiment run queries, model preference keys, and composer draft helpers live under `lib/`.
- The chat store is still one `useChatStore`. Send, tabs, plan, and the composer queue live in `stores/chat/` files; the published names (`sendPrompt`, `loadSession`, `approveAndExecutePlan`) did not change.
- Renderer stores talk to the desktop through `lib/desktop-api/` (literature, extract, experiment, git, fs, project, workbench, execution, agent, research, settings, compile, terminal, log, commands, teams, MCP, browser, Pro license). The rest of the renderer uses the same ports — only `lib/desktop-api/` talks to `window.electronAPI`.
- Git orchestration and template apply flows now go through `lib/desktop-api/` (`git`, `template`, `fs`). Settings prompt/knowledge/rules/backup panels load through `lib/settings/` instead of calling the bridge from the component.
- Settings literature, workspace, general, teams list/create, commands, and MCP panels now go through store or `lib/desktop-api/` helpers. Research brief read/open and workspace folder autosave use the same ports.
- Settings Skills list, library, and SKILL.md editor now go through `lib/settings/skills.ts`. Slash-command catalog and “reveal in Finder” use the same skill and shell ports.
- Settings subagent and orchestrator editors now go through `lib/settings/subagents.ts`. Chat composer mention lists use the same subagent list.
- Settings provider editor (test connection / list models) and the system-font picker now go through `lib/providers` and `lib/theme`. Model catalog prefetch and effort lists use the same agent port.
- Settings About (version, check/download/install, legal links) and the sidebar update chip now go through `lib/updates` and the shell port. Shortcut labels read the host platform from the same shell helper.
- Settings team detail now goes through `lib/settings/teams.ts` (inventory, roster overrides, icon, install/uninstall). The shared teams store still owns the catalog list.
- Literature library helpers and the literature mode UI (PDF attach, reader, citations, Zotero bind) now go through `lib/desktop-api/` (`literature`, `extract`, `fs`, `agent`, shell). The literature store was already on that port.
- Experiments mode (create/edit from brief, compare, artifacts, provenance, registry-changed refresh) now goes through the experiment, fs, and research ports. The experiment store was already on that port.
- Template Center (list, preview, PDF, apply state in `.workbench/settings.json`) now goes through the template and fs ports. Apply-template flow was already on that port.
- Git mode commit detail, file diffs, and worktree-merge branch lookup now go through the git port. The git store was already on that port.
- Terminal mode (PTY create/write/resize, data/exit events, job cancel, clear/kill) now goes through the terminal and execution ports. The terminal store was already on that port.
- Chat markdown images/PDFs and Interaction (panel, plot CSV, thumbnails, registry-changed focus) now go through the fs, literature, and interaction ports.
- Browser, TeX workspace, and Files sidebars now go through the browser, compile, and shell ports. Opening a project file from chat uses the fs port.
- Chat composer attach/drop, vision fallback, ask-question, context compact, active-team picker, and compile-prompt context now go through the fs, dialog, agent, git, teams, and literature ports.
- Renderer hooks (agent events, compile preview, close-tab, tray, window state, skills refresh) now go through the agent, compile, and shell ports.
- Title bar, main toolbar, window controls, and the renderer bootstrap platform tag now go through the shell port and the shared window-state hook.
- App shell, left sidebar, and RightArea now go through the execution, settings, agent, fs, and browser ports (job events, glass theme, session list/delete, file watch, in-app browser open).
- Command palette, Teams Center, builtin actions, PDF preview, project/team icons, and the agent status dot now go through the same ports. Renderer code outside `lib/desktop-api/` no longer calls the bridge directly.
- Switching the focused project only goes through `lib/workspace/project-lifecycle`. The file tree updates; chats from the previous project stay alive.
- RightArea tabs are a `kind` discriminated union. Mode and editor code narrows on `tab.kind` instead of a flat optional payload.
- Experiments Run in Ask mode uses the same permission card as chat. The private confirm modal is gone; 60s auto-deny stays on that shared card.
- Main-process code now lives in domain folders (literature, experiments, compile, git, and the rest) instead of a flat services drawer. Opening a library, compiling, or running an experiment still uses the same desktop commands.
- The literature library now lives at `src/main/literature/` (same level as agent and workbench). Callers import the facade or the domain file; the old flat `services/literature-*.ts` leftovers and the nested `services/literature/` tree are gone. PDF protocol registration stays in the app host; the domain no longer imports Electron.
- Catalog lookup (Crossref, arXiv, OpenAlex, and the rest) now runs in the main process. Shared bibliographic-metadata keeps parsers and types only — it no longer talks to the network.
- Main-process `lib/` no longer imports `services/`. TeX engine / bib-tool detection lives in `lib/tex-detect`; workspace folder reads used by bib-path resolution live in `lib/workspace-dirs`.
- Experiments now live at `src/main/experiment/` (registry CRUD, runs, venv gate, executor, provenance). The old `services/experiment-log-service.ts` monolith is gone; the domain no longer imports Electron.
- LaTeX compile now lives at `src/main/compile/` (orchestrate, Tectonic daemon, manuscript export). Engine detection stays in `lib/tex-detect`; the compile domain no longer imports Electron.
- Git CLI operations now live at `src/main/git/` (exec, status, stage, branch, log, merge, commit, worktree). Shared git types stay in `src/shared/git/`; IPC channel files stay in `ipc/git.ts`.
- Terminal (PTY, bash jobs, execution registry) now lives at `src/main/terminal/`. Project filesystem, workspace folders, and lifecycle authority now live at `src/main/project/`.
- Session sidecars (chat registry, display/context stores, citation appendices, composer attachments, project prewarm) now live at `src/main/session/`. Skills install/sync/registry live at `src/main/skills/`. Research plan/brief and interaction specs live at `src/main/research/` and `src/main/interaction/`.
- Team leftovers (install store, license, user teams, subagents sync, pro discovery, project MCP defaults) now live in `src/main/teams/`. Task-orchestrator gate and vision fallback live in `src/main/agent/`. The provider-chat HTTP helper lives in `src/main/lib/` so the literature domain does not import agent. Rules/prompt sync live in `src/main/prompts/`.
- Host shell leftovers (settings, tray, desktop notifications, update checker, glass vibrancy, system fonts) now live in `src/main/app/`. The flat `src/main/services/` drawer has no TypeScript sources left.
- File, folder-picker, new-project, and manuscript-template IPC now live in four channel-family files (`ipc/fs.ts`, `ipc/dialog.ts`, `ipc/project-scaffold.ts`, `ipc/template.ts`). The channel strings are unchanged — opening a folder, creating a project, and applying a template still use the same names.
- Literature, extract, Zotero, and bibliography IPC handlers now call `literature/host` (plus native dialogs). Progress still goes to the window that started the download; the channel names are unchanged. Domain tests keep importing `literature/facade` so they do not load the desktop settings store.
- The desktop bridge is split by domain (`src/preload/fs.ts`, `literature.ts`, `agent.ts`, and the rest). `electronAPI` method names are unchanged — after this update, quit and reopen the app so preload reloads.
- Literature, experiment, git, and chat stores now talk to the desktop through `lib/desktop-api/` instead of calling `window.electronAPI` directly. Chat widgets use the same ports.
- Shared contracts no longer pretend to be main-process services. `@shared/*` now resolves only to `src/shared/`. Permission modes, log types, tool catalog, workspace folders, and command types live in shared; the renderer no longer imports main through an alias.
- Literature, citation-health, extract, citation-network, and git/worktree payloads now have one TypeScript source in `src/shared/`. Settings and the renderer no longer keep a second copy of those shapes. The conversation reducer lives in shared so main and the UI project the same event stream.
- Shared contracts now live in domain folders (permissions, literature, agent, workbench, and the rest). Disk checks for interaction plots and figures moved out of shared into the main process. The leftover one-line re-export files at the shared root are gone — imports use the domain path.

### Chat

- On an empty chat, the composer eases between the centered and bottom-docked positions when the center column crosses the width threshold (opening RightArea, resizing). The two layouts were `justify-center` / `justify-end`, which cannot interpolate. They are now the same column with a trailing flex-grow spacer, using the same 220ms curve as the side panels — one motion, not a staged rise then widen. The title-bar maximize cluster follows the live open mark written when the panel actually moves (same idea as the left sidebar). A delayed close used to flip the store to “closed” while the panel was still open; sash `onResize` then wrote “open” back, and the buttons stuck after the panel finished retracting.
- Model names in the composer picker stay on one line (name + effort + check). A shared menu change for the Default badge had been wrapping every row and splitting short names like Hy3 Low.
- Scrolling the composer model list no longer lets rows peek through above the search bar — the search stays fixed and only the list scrolls.
- The empty homepage composer has a project picker to the left of the branch selector. The dropdown is the same panel as Workbench Add — search, recents, Open Folder, New Project — so a new chat can bind to a folder that is not already on the workbench. Picking a listed project keeps this empty session (it does not open another chat). The control locks while the agent is running. Once the chat has messages, the picker is gone — that session stays on its project.
- After the first reply in a new chat, PrismNext asks the model for a short title and replaces the first-message placeholder. A name you type yourself is left alone; later turns do not run this again.
- The session hover card now shows the real git branch. A worktree is labeled as a worktree, with its branch underneath (and what it merges into). The card is smaller and tighter. Hover a chat in the left sidebar to open the same card to the right. Title-bar session tabs use a pointer cursor. The card shows the session’s absolute checkout path. A folder that is not a git repository no longer throws `not a git repository` in the main process.



### Git

- The Git panel now shows whether the current branch is ahead or behind its remote (`↑2 ↓0 · origin`), or that there is no remote / no upstream. This works with any git remote (GitHub, GitLab, Gitea, a lab server) — it is not GitHub-only. After a push, those counts refresh; a failed push shows the git error.
- Commit sits beside **Push** / **Publish** when there is something to send. The ⋯ menu can Fetch, and Pull when the branch is behind. Pull is fast-forward only — if the branch has diverged, the error tells you to rebase or merge in the terminal. After a commit, the toast can offer Push.
- First publish no longer always uses `origin`. A single remote, `origin`, or `branch.*.pushRemote` is enough; if several remotes exist and none is obvious, you pick one. The ⋯ menu lists remotes (read-only) and can Fetch all of them or open Terminal. A rejected non-fast-forward push explains fetch / rebase — there is still no force-push button.
- After a feature branch is pushed, the Git panel can create a GitHub pull request with the GitHub CLI (`gh`). The ⋯ menu opens a small dialog (title, base, head, optional body, draft). If `gh` is missing or you are not logged in, the item stays disabled and you can copy a `gh pr create` command, Ask Agent (fills the composer, does not send), or open the GitHub CLI install page. A successful push can offer Create PR on the toast. GitLab / other hosts are still Push-only.
- After **Merge to Branch** from a worktree, the success toast can offer **Go to Local** and **Push** the branch you merged into (or **Create PR** if that branch is already pushed and is not the default). The worktree toolbar still only has Merge.
- History commit detail: the ⋯ actions menu is pinned to the right end of the header again (it had been sitting next to the timestamp).
- History and Changes now show `+` / `-` line counts for new and deleted files. The first commit in a repo was listed as “no file changes” because `diff-tree` skipped the root; untracked new files were hard-coded to 0/0.
- Changes list puts `+` / `-` next to the file name (not at the far right with New/Deleted). The filter chip has no fill; counts sit after the label and turn green/red on hover. In the menu, each row keeps counts beside the name and only the checkmark on the far right.
- When a repo has no remote, the Git badge is **Add remote** (also in the ⋯ menu). Paste an HTTPS or SSH URL; the name defaults to `origin`. This only stores the address — Publish still sends the branch. You still create the empty repo on GitHub/GitLab yourself.
- Changes filter now has **Last agent turn** (current chat’s latest Agent turn ∩ still-dirty files) and a **Commits** submenu on feature branches (`main`/`master`..HEAD, 20 commits with +/-). Picking a commit opens the existing commit detail in the center; History stays on the sidebar. Spec: `docs-private/specs/2026-08-25-git-changes-lens-spec.md`.
- Last agent turn stays selectable when the list is empty (the page just says there are no files). Filter rows now have Cursor-style icons: last turn, uncommitted, staged, unstaged, and Commits.
- Feature branches also get **Branch changes**: the net `default...HEAD` file list (not the sum of each commit). Individual commits stay in the Commits submenu. Hidden on `main` / `master`.
- When the current Changes filter has no files, the center shows shortcut entries (like Files / Browser recents). If that filter has files, the old file list + diff is unchanged.
- Git TabToolbar and the Changes filter row share the same left inset and icon size, so the branch chip and the lens chip line up. Discard and stage on that header stay on the same right edge as the file rows.

### Workbench

- Opening the app returns to the project and chat tabs you had when you quit, not a new chat on the default project. If that folder is gone from the workbench, you land on the default project. If the last chat is gone, you get a new chat in the last folder.
- The default project can leave the workbench like any other folder (the folder and its chats stay on disk). Add it back from the + panel — it always appears in Recents, marked Default. The Default mark sits next to the project name (sidebar row, Updated second line, menus), not at the far right. Chat’s project picker uses the same mark, and still offers that folder when it is not on the workbench. There is no “no project” option: a session always belongs to a real project.
- Removing the default project from the workbench no longer crashes the sidebar. The default-as-member helpers now return a stable object when that folder is off the list; a new object every render was sending React into `Maximum update depth exceeded`.
- Drag a project row in the left sidebar to change the workbench order. Hover keeps the pointing hand; the grab cursor appears only while you are dragging. Dropping at the top or bottom no longer needs a pixel-perfect line — the pointer can leave the list (Pinned, footer, empty space) and the ends have a larger snap zone. Long lists scroll when you hold near the edge. After a drag, the next click expands or collapses that project — it is no longer swallowed. The default project stays in the list — it is a real project, not a hidden “no project” bucket — and can sit anywhere. Chat’s project picker follows the same order.
- Filter groups chats as Workbench (by project) or Updated (by date, newest first, title then project). Status is a placeholder. The bottom row is Expand All when no project folder is open, otherwise Collapse All — same rule as the file tree. In Updated, the dot, time, and archive sit on the title row; the project name is the second line only.
- Workbench header Filter and Add sit a bit farther apart. Hover and an open menu fill the same opaque accent as a selected row — the icons stay caption-sized.
- The Add project panel still lists recents that are already on the workbench; those rows are quieter (muted), not labeled. Click one to switch to that project and start a new chat. The panel sizes and flips with the window, like the composer model picker — it is not pinned to the trigger’s bottom-right.
- Workbench projects no longer have a custom icon. The row uses a folder mark that opens when you expand the project (same folder language as Add project). New Project, Edit, and Settings → Workspace no longer ask for an icon; the app no longer writes `projectIcon` or `icon.png`.
- The Workbench “+” panel is search, recents, then Open Folder / New Project pinned at the bottom. Recents come from the old welcome list (full path, 8 then More) and skip folders already on the workbench. There is no remote/GitHub repos section yet.
- Archived is a footer icon next to Settings (left to right, no divider). Settings shows its shortcut in a tooltip, not a kbd on the row. Archived chats are one flat list: title, then a folder mark, short path, and name. Filter only sorts; Add stays on the Workbench header. Project right-click (Edit / Archive all / Remove) has no divider.
- Pinned / Workbench / Settings group labels stay the smaller caption size so they read as headings, not as another row. Header icons (archive, filter, sort, add, Pinned chevron) match that caption scale. Idle row text in both sidebars is `text-muted-foreground` — a bit softer than the previous sidebar-foreground labels.
- Collapsed workbench projects stay 2px apart. After an expanded project's last chat, the next project gets 8px (`pt-2`) so the open group reads like Cursor's agent sidebar.
- Right-click a workbench project for Edit, Archive all, and Remove. The row only keeps “+” for a new chat in that project. The folder mark opens when the project is expanded. Edit is just the workbench name. The default project cannot be removed.
