External discovery hits now return full abstracts (only extreme outliers truncated) so the model can screen candidates properly.

Settings → Prompt stack preview shows that same live join — not the old OpenCode `agent.md` bake-in — so what you read in Settings is what the model gets. ### Literature

## 0.9.0 — 2026-08-31

### Remote

- Remote TeX projects no longer auto-compile on every pause in typing. The switch is remembered per folder: local stays on unless you turned it off; remote starts off and only runs when you compile (or turn the switch on for that project). Binding that preference must wait a tick — doing it while the store module loads crashed the renderer (`useDocumentStore` before init), so the window never came up.
- Remote TeX compile now hands the PDF bytes to the preview after Host finishes. We used to write `os.tmpdir()` (`/var/folders/…/prismnext-remote-…pdf` on macOS) and ask the renderer to `fs:readBytes` it — that path is outside `~/`, so TeX Workspace always failed with “Path outside user home” even when `.workbench/compile/` on the server already had the PDF.
- Opening a remote folder from Chat’s project picker (host submenu → Open Folder) now binds that empty chat to the remote project — name, Host, send target, and file tree stay together. The same picker used to run a hardcoded workbench focus only, so an empty homepage tab stayed on the local project (`test1`) while Host showed the server IP.
- Opening a remote copy of a folder that already exists locally no longer hijacks that local workbench row. Host still reuses `.workbench/workbench.json` id; the laptop now mints a new id (same rule as opening a second local copy) and writes it back to the server.

- Switching to a remote project while that Host is already connected now fills the file tree, Settings → Workspace folders, TeX manuscript folder, library, and experiments. We used to skip that bind whenever focus said “do not start SSH,” even if SSH was already up — so Files looked empty until Refresh, function-folder icons vanished, TeX said “No manuscript folder configured,” and Workspace settings sat on “Loading…”. Host still down: skip as before (no hang). When the Host later becomes ready, the same neighbors refresh without you clicking Refresh.
- `template:listBackups` on a remote project no longer throws `remote_project_root_is_not_local` into the desktop log. Template backups are still local-only (empty list on remote until Host grows that API).
- Dragging or picking a PDF into a remote library now copies the file onto the server (`.workbench/uploads/literature/`) before Host ingest. Previously the Host tried to `readFile` a path that only exists on this computer. Papers larger than 40 MB are refused with a toast.

- Homepage Connect (next to Host) now has a light outline; hover follows Brand (`primary`) instead of turning near-black. Switching to a remote project that is not connected no longer shows Init Git — we were treating “Host is down” as “this folder has no repo.” The toolbar hides Git until we know, or shows the last branch we saw on that host (remembered on this computer). Git’s empty state says to connect instead of offering Init.
- Files, Git, TeX, Terminal, library, experiments, Plan, and Interaction on an unconnected remote project no longer pretend the Host is there. The tab strip stays; the mode toolbar and sidebar hide; the pane is a centered Connect. Browser (this computer) and Settings still work. Host-bound tabs in the background are not kept mounted, so they do not probe SSH.
- Opening a remote chat without SSH no longer dumps `git:branches` / `agent:syncIntensiveReading` “Not connected” into the desktop log — those probes return empty until you send or tap Connect. Sending right after connect no longer races session sync against `agent:send` on the same Host pipe (that was the `Host control plane dropped` line under your message). TCP health checks also no longer steal the Host’s one client socket. If the pipe still blips, the turn says to send again after reconnect — not the raw `RemoteOperationError`.
- Remote chats now have a laptop copy. After a Host is ready, sessions sync into `~/.prismnext/remote-cache/…`. Cold start shows those lists without SSH. Clicking a remote session opens the same tab you would see online — you can read and type. Sending (or the Connect button to the right of Host) is what starts SSH. The “planning next step” line follows the connect gates and opens the same dialog; one-click / send closes it when ready. Opening Connection status from the Host menu still stays open.
- Switching an empty chat to another project no longer talks to a down Host. A local folder stays on this computer (the previous remote tab is forgotten). Reassign on a host that is not up yet is recorded here until you send.
- Connecting no longer looks like it “goes back to SSH” after Handshake. That line was leftover copy tagged as the SSH step, so the progress bar jumped back to SSH and spun while the Host was actually doing listen / handshake / Pro packs / doctor. Same SSH session — not a second login.
- The project picker is wider. Local recents put the folder path on the same line as the name (remote rows already show the IP). Repos host rows keep Connected / Connecting on the same line as the IP. Path and IP sit after the name — the right edge is only the current-project check, or a hover × that drops that folder from Recents. A folder already on the workbench is no longer dimmed: the name stays normal, the path / IP stays muted.
- The remote host submenu no longer has a Connect row that only opens the connection dialog. Open Folder and New Project still start SSH, but the progress (and host-key Trust) stays in that folder / new-project panel. The first row in a Repos submenu is no longer flush against the border. New Project is as wide as the command palette; picking a remote parent expands in the same dialog instead of stacking a second folder window. Location is one field (no nested frames or extra rules); type sizes follow the dialog tokens; Use this folder is a quiet ghost action. A rule sits under the location path. Below it, a path field (`/home/…`) uses the UI font (not Editor / mono) and jumps on Enter. Enter lists the typed path; if it is missing, we create that last segment over SSH (so an older Host without `fs:mkdirDir` still works). There is no separate Create folder action. Parent folder uses an up-folder icon so it is not the same as the folders below. Use this folder stays at the bottom.
- Worktree lives under Host, not as its own toolbar button and not under Branch. Local opens Local / SSH / New Worktree; Worktrees ▸ only appears when an open worktree already exists. Click New Worktree (or the current worktree) again to leave it — there is no nested “Project” row. A remote host opens the IP, Connection status (the same dialog), then the same worktree rows. The Host label becomes `Local · Worktree` / `IP · Worktree` until a named checkout exists, then `Local · wt-name`. The button uses the same Workflow icon as Git’s toolbar. New is still lazy (created on the first message). `/worktree` stays as a shortcut.
- Chat’s homepage toolbar now has a Host control instead of the Worktree button. A remote project shows the server IP (read-only). A local project shows Local and can open the SSH picker without leaving the folder. A chat with messages shows the project name and host as read-only text.
- The connection panel now shows a step progress bar and a collapsed log. Each gate is one line (name · detail). When the host is ready it stays open so you can read the log — Continue opens the folder / new project / chat; Close just dismisses it.
- Switching the sidebar to another remote project no longer opens SSH. Chats for a project you removed from the workbench still show up in the time-grouped list (name + host). Clicking a remote chat connects if needed — the connection panel stays up until you continue or close it. Two projects on the same host switch by rebinding the folder; SSH stays up.
- The project picker (Workbench “+” and Chat) now mixes local and remote recents. Remote rows show the host on the right. Repos lists Local first, then each SSH host. The footer has Open, New, and Connect via SSH.
- Sidebar now lists chats for **every** remote workbench project, not only the one currently bound on SSH. Switching focus no longer empties the other project's session list (offline copies still show until you reconnect).
- Picking a remote project from Chat updates that tab's project: the toolbar label, send target, and file tree stay on the same folder. A tab that already has messages cannot switch project — you get a toast and keep the current chat.
- Reconnect now actually installs Tectonic into `~/.prismnext-host/current/bin/tectonic`. Two bugs stacked: production SSH treated a missing file as size 0 (so install was skipped), and a GitHub cache named `.tar.gz` that is actually a raw ELF was unpacked with `tar` and never copied into `bin/`. The installer now accepts that ELF, and connect fails if the dest file is still missing.
- Host `install-runtime` no longer treats a leftover `bin/tinymist` (or Tectonic) **directory** as “already installed.” Linux `-x` is true for directories; this computer’s check is `[ -f ]`, so the log said ready while connect failed with `bin/tinymist is still missing`. Skip / success now require a non-empty regular file; a leftover directory is replaced. Curl no longer prints a progress meter over the install log. Reconnect after `pnpm host:pack` so the server gets the new installer.
- Remote compile no longer pretends the server needs TeX Live / `xelatex`. PrismNext uses Tectonic there (`~/.prismnext-host/current/bin/tectonic`). If that file is missing, the error says so and asks you to reconnect so the Host can download it. The connection doctor line now reports Tectonic too.
- New Project on a remote host uses the same panel as a local project: name, parent folder on that server, workspace preset, and optional Git. It no longer creates an empty folder and hopes Setup will finish the job. The parent picker now expands under Location in that same dialog. - Terminal quick commands on a remote project are stored on that machine (`.workbench/terminal/config.json`), not in a folder on this computer.
- Plan draft Approve & Build now works on a remote project: claim / read / promote / discard go to the Host (the draft lives on the server). The interaction-open panel also reaches this computer — Host broadcasts `interaction:changed` over the control plane instead of a missing Electron window.

Session tab and sidebar use the same card; IP and connection sit on one line. The sidebar no longer appends a Remote label. LaTeX is probed separately for this computer and each connected Host — opening a remote project no longer overwrites the local engine. “Not detected” uses a warning color, not a faded icon. Remote LaTeX now looks in `~/.prismnext-host/current/bin/tectonic` (the copy `install-runtime` downloads), not only next to `process.execPath` or on the system PATH — a Host started with system Node no longer reports “not detected” after Tectonic is installed.

- Connecting pushes only the Host program (JS + Core teams + pin files). The Linux server then downloads official Node, portable Git, and Tectonic into `~/.prismnext-host/current/` and puts them on the Host PATH. You do not `apt install` them, and this computer does not ship those binaries in the PrismNext installer or over SSH. Experiment Python / venv is still the project’s own environment. The server must be able to reach nodejs.org and GitHub — the same network remote Chat already needs.

Host PTY now unlocks `/dev/ptmx` (`unlockpt` / `TIOCGPTN` via system perl) and sets a controlling tty, so remote bash has job control and the kernel emits CRLF. The previous open-and-probe path left the slave locked, silently fell back to a pipe, and xterm painted the MOTD as a staircase. Display also treats LF as newline+return (`convertEol`) so local and remote stay aligned if a chunk is LF-only. The tab is labeled `bash · 远程`.

The live pane no longer draws a Brand bar across the top on each keystroke. `.typ` buffers use a CodeMirror Typst highlighter (markup / `#` code), not Plain Text.

The agent compiles `.tex` with LaTeX tools and `.typ` with Typst tools, and no longer talks about a TeX Workspace.
