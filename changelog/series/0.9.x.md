## 0.9.0 (Unreleased)

### Remote

- Homepage Connect (next to Host) now has a light outline; hover follows Brand (`primary`) instead of turning near-black. Switching to a remote project that is not connected no longer shows Init Git — we were treating “Host is down” as “this folder has no repo.” The toolbar hides Git until we know, or shows the last branch we saw on that host (remembered on this computer). Git’s empty state says to connect instead of offering Init.
- Files, Git, TeX, Terminal, library, experiments, Plan, and Interaction on an unconnected remote project no longer pretend the Host is there. The tab strip stays; the mode toolbar and sidebar hide; the pane is a centered Connect. Browser (this computer) and Settings still work. Host-bound tabs in the background are not kept mounted, so they do not probe SSH.
- Opening a remote chat without SSH no longer dumps `git:branches` / `agent:syncIntensiveReading` “Not connected” into the desktop log — those probes return empty until you send or tap Connect. Sending right after connect no longer races session sync against `agent:send` on the same Host pipe (that was the `Host control plane dropped` line under your message). TCP health checks also no longer steal the Host’s one client socket. If the pipe still blips, the turn says to send again after reconnect — not the raw `RemoteOperationError`.
- Remote chats now have a laptop copy. After a Host is ready, sessions sync into `~/.prismnext/remote-cache/…`. Cold start shows those lists without SSH. Clicking a remote session opens the same tab you would see online — you can read and type. Sending (or the Connect button to the right of Host) is what starts SSH. The “planning next step” line follows the connect gates and opens the same dialog; one-click / send closes it when ready. Opening Connection status from the Host menu still stays open.
- Switching an empty chat to another project no longer talks to a down Host. A local folder stays on this computer (the previous remote tab is forgotten). Reassign on a host that is not up yet is recorded here until you send.
- Connecting no longer looks like it “goes back to SSH” after Handshake. That line was leftover copy tagged as the SSH step, so the progress bar jumped back to SSH and spun while the Host was actually doing listen / handshake / Pro packs / doctor. Same SSH session — not a second login.
- The project picker is wider. Local recents put the folder path on the same line as the name (remote rows already show the IP). Repos host rows keep Connected / Connecting on the same line as the IP. Path and IP sit after the name — the right edge is only the current-project check, or a hover × that drops that folder from Recents. A folder already on the workbench is no longer dimmed: the name stays normal, the path / IP stays muted.
- The remote host submenu no longer has a Connect row that only opens the connection dialog. Open Folder and New Project still start SSH, but the progress (and host-key Trust) stays in that folder / new-project panel. The first row in a Repos submenu is no longer flush against the border. New Project is as wide as the command palette; picking a remote parent expands in the same dialog instead of stacking a second folder window. Location is one field (no nested frames or extra rules); type sizes follow the dialog tokens; Use this folder is a quiet ghost action. A rule sits under the location path. Below it, a path field (`/home/…`) uses the UI font (not Editor / mono) and jumps on Enter. Enter lists the typed path; if it is missing, we create that last segment over SSH (so an older Host without `fs:mkdirDir` still works). There is no separate Create folder action. Parent folder uses an up-folder icon so it is not the same as the folders below. Use this folder stays at the bottom.
- Worktree lives under Host, not as its own toolbar button and not under Branch. Local opens Local / SSH / New Worktree; Worktrees ▸ only appears when an open worktree already exists. Click New Worktree (or the current worktree) again to leave it — there is no nested “Project” row. A remote host opens the IP, Connection status (the same dialog), then the same worktree rows. The Host label becomes `Local · Worktree` / `IP · Worktree` until a named checkout exists, then `Local · wt-name`. The button uses the same Workflow icon as Git’s toolbar. New is still lazy (created on the first message). `/worktree` stays as a shortcut.
- Chat’s homepage toolbar now has a Host control instead of the Worktree button. A remote project shows the server IP (read-only). A local project shows Local and can open the SSH picker without leaving the folder. A chat with messages shows the project name and host as read-only text.
- The connection panel now shows a step progress bar and a collapsed log. Each gate is one line (name · detail). When the host is ready it stays open so you can read the log — Continue opens the folder / new project / chat; Close just dismisses it.
- Switching the sidebar to another remote project no longer opens SSH. Chats for a project you removed from the workbench still show up in the time-grouped list (name + host). Clicking a remote chat connects if needed — the connection panel stays up until you continue or close it. Two projects on the same host switch by rebinding the folder; SSH stays up.
- The project picker (Workbench “+” and Chat) now mixes local and remote recents. Remote rows show the host on the right. Repos lists Local first, then each SSH host. The footer has Open, New, and Connect via SSH.
- Sidebar now lists chats for **every** remote workbench project, not only the one currently bound on SSH. Switching focus no longer empties the other project's session list (offline copies still show until you reconnect).
- Picking a remote project from Chat updates that tab's project: the toolbar label, send target, and file tree stay on the same folder. A tab that already has messages cannot switch project — you get a toast and keep the current chat.
- Reconnect now actually installs Tectonic into `~/.prismnext-host/current/bin/tectonic`. Two bugs stacked: production SSH treated a missing file as size 0 (so install was skipped), and a GitHub cache named `.tar.gz` that is actually a raw ELF was unpacked with `tar` and never copied into `bin/`. The installer now accepts that ELF, and connect fails if the dest file is still missing.
- Remote compile no longer pretends the server needs TeX Live / `xelatex`. PrismNext uses Tectonic there (`~/.prismnext-host/current/bin/tectonic`). If that file is missing, the error says so and asks you to reconnect so the Host can download it. The connection doctor line now reports Tectonic too.
- New Project on a remote host uses the same panel as a local project: name, parent folder on that server, workspace preset, and optional Git. It no longer creates an empty folder and hopes Setup will finish the job. The parent picker now expands under Location in that same dialog. Custom folders are denser: Add folder is a text action, name and type sit on h-6 rows, and the type menu uses the same compact select as Settings.
- Opening a remote project now fills `.workbench` and the default function folders on the server (for example `manuscript/`). Settings → Workspace writes to that machine; if SSH is down, save fails instead of pretending it worked.
- Reconnecting to a server that already has this app’s Host, Node, Git, and Tectonic no longer walks the download steps. Only a missing engine is installed (for example Tectonic alone). The connection log says so instead of “installing the environment.”
- Terminal quick commands on a remote project are stored on that machine (`.workbench/terminal/config.json`), not in a folder on this computer.
- Plan draft Approve & Build now works on a remote project: claim / read / promote / discard go to the Host (the draft lives on the server). The interaction-open panel also reaches this computer — Host broadcasts `interaction:changed` over the control plane instead of a missing Electron window.
- Titlebar status is app-wide: every live remote Host is one IP row, and the local Agent row stays even when you are on a remote project. Git / folder stay on the session hover. Session tab and sidebar use the same card; IP and connection sit on one line. The sidebar no longer appends a Remote label. LaTeX is probed separately for this computer and each connected Host — opening a remote project no longer overwrites the local engine. “Not detected” uses a warning color, not a faded icon. Remote LaTeX now looks in `~/.prismnext-host/current/bin/tectonic` (the copy `install-runtime` downloads), not only next to `process.execPath` or on the system PATH — a Host started with system Node no longer reports “not detected” after Tectonic is installed.

- Connecting pushes only the Host program (JS + Core teams + pin files). The Linux server then downloads official Node, portable Git, and Tectonic into `~/.prismnext-host/current/` and puts them on the Host PATH. You do not `apt install` them, and this computer does not ship those binaries in the PrismNext installer or over SSH. Experiment Python / venv is still the project’s own environment. The server must be able to reach nodejs.org and GitHub — the same network remote Chat already needs.
- Launch restore remembers a remote project path and its chats, but does **not** SSH on startup. Connecting on open made the app feel stuck. Reconnect stays a later, explicit action.
- The terminal on this computer now opens at the panel size (not a hardcoded 80×24), so Python / rich / progress bars wrap correctly before any remote is involved. Host PTY now unlocks `/dev/ptmx` (`unlockpt` / `TIOCGPTN` via system perl) and sets a controlling tty, so remote bash has job control and the kernel emits CRLF. The previous open-and-probe path left the slave locked, silently fell back to a pipe, and xterm painted the MOTD as a staircase. Display also treats LF as newline+return (`convertEol`) so local and remote stay aligned if a chunk is LF-only. The tab is labeled `bash · 远程`.
- Remote Chat can use Pro teams when this computer has an active Pro license. Connecting pushes Pro packs to `~/.prismnext-host/pro-package/` (not the public Host tarball) and sends a session grant **without** the activation key. After the packs land, Host writes install records for those team ids — discovery alone left them as `not-installed`, so remote Chat could not run Idea Arena. The Host ignores leftover `license.json` on the server. Clearing or expiring Pro on this computer revokes the grant on the live Host; disconnect does the same. The activity-team picker is the **same list** as a local project (Core / Pro / 通用团队). Switching the remote active team writes only the team id into that folder’s `teams.json` on the Host. After a Host payload push, a still-running listen process is killed when `stamp.json` changes so the new runtime actually loads.


- Remote hosts are read from this computer’s `~/.ssh/config` (including `Include`). You do not fill host / user / key in Settings. Open the Workbench add-project menu to see the list and connect.
- Connection uses the system `ssh` / `scp` already on your PATH, so ProxyJump, ssh-agent, and your existing keys work the same as in a terminal. A first-time host key is confirmed in the connection panel, then written to `~/.ssh/known_hosts`.
- The first successful connect still pushes this app’s Host program from the notebook (stamp = app version + checksum). A missing local payload fails locally. Node, Git, and Tectonic are downloaded on the server from those pins.
- Remote Workspace is a core capability: connect, Host, and remote Chat do not require a Pro license. The host list comes from `~/.ssh/config`.
- Chat’s Local / worktree control is unchanged — it is still the git checkout switch, not the remote-machine switch. Creating or switching a worktree on a remote project now runs on the Host: checkout lands in the server’s `~/.prismnext/projects/<id>/worktrees/`, and the app keeps talking to it as `remote://…`. Host file ops and the remote terminal may use that hangar for the bound project (not another project’s, and not `/etc`). Chat’s worktree cwd is the checkout, not the paper root.
- First connect after SSH succeeds no longer dies with “could not resolve remote $HOME”: the system `ssh` command is sent as one script, so `$HOME` is expanded on the server.
- Connect now keeps a constitution: each gate (payload, SSH, host key, home, push, Node, host process, handshake, doctor) is logged and shown in a dedicated connection panel, not inline in the Workbench add menu. License is not a connect gate.
- Connecting no longer requires Node on the server PATH. After the Host program lands, the server downloads a dedicated Linux Node 24 LTS into `current/bin/node` and starts `prismnext-host` with that binary.
- After a host is connected, the Workbench add menu opens a second-level list for that machine: recent remote projects, Open Folder, and New Project. Connecting does not open `$HOME` as a project; you pick a folder first. The file tree and editor talk to that folder over SSH. The sidebar shows that machine’s HostName (usually the IP) after the project name.
- Remote Chat now runs on the Host: send / stop / sessions / permissions go over SSH. The Host calls the model vendor directly. Connecting seeds API keys from Settings → AI; the server stores them as AES-256-GCM ciphertext in `~/.prismnext/host-model.json` (0600). The unwrap key stays on this computer (`safeStorage`). The laptop Gateway is an opt-in fallback when the server cannot reach the vendor. Chat UI is unchanged.
- Small laptop attachments (≤5 MB) are copied into the remote project’s `.workbench/uploads/` before the turn starts. Larger files are refused with a toast.
- Literature, LaTeX, Plan drafts, and Interaction tools on a remote project run on the Host. Experiment runs on the server, and say so if SSH drops.

### UI
- Dialogs follow Settings → Appearance: UI Font family (`--font-sans`) and rem sizes that scale with UI Font size. Title / description use `--font-dialog-title` / `--font-dialog-label` (same as Settings pages) instead of Tailwind `text-lg` / `text-sm` or a missing `--font-size-15`. Fields use the Settings form size. Action buttons stay `size="xs"` (h-6). New Project, SSH picker, Git, literature, experiments, and the rest share this chrome.

Host serves terminal quick-command config from the server `.workbench/terminal/config.json`.
- `pnpm host:pack` ships a slim `prismnext-host.tar.gz` (Host JS, Core teams, `bin/install-runtime`, pin files). It does not download or embed Node / Git / Tectonic. Pins live in `scripts/host/node-version.txt`, `scripts/host/git-version.txt`, and `scripts/host/tectonic-linux.txt`. On connect, the server runs `install-runtime` (checksummed HTTPS). Host `main` prepends those bins to PATH; the SSH listen/stdio launch no longer inlines PATH. Git panel methods (`git:*`) and worktree methods (`worktree:*`) route to the Host for `remote://` projects. `researchPlan:*` and `interaction:*` do the same; Host `interaction-open` emits through the control-plane event sink. Host PTY unlocks `/dev/ptmx` via perl ioctl (no python3, no node-pty on Host); `script` is the Linux fallback; pipe output is translated to CRLF. xterm `convertEol` is on.

- New `src/shared/remote` contracts (`ProjectHandle`, SSH frames, Host handshake, `SshConfigHost`) and a `prismnext-host` control-plane binary (`doctor`, `serve --stdio`) packed with `pnpm host:pack` into `out/host/` / extraResources. Transport default is system OpenSSH; the unused `ssh2` / `@types/ssh2` packages were removed. Remote Workspace is not a Pro entitlement (`workspace.remote` / `agent.remote` were never shipped). Default model path is remote BYOK (`host-model.json`); Gateway allowlist (still derived from `PI_PROVIDERS` plus user `aiBaseUrls`) is opt-in. The turn carries `provider` / `modelId` / `permissionMode`.
- Host payload filename is the arch-independent `prismnext-host.tar.gz`. Connect still reads remote `uname -m` so the server downloads the matching Linux Node / Git / Tectonic.
- Host pack now includes the Pi Agent (`agent:*`, ~18.5 MB JS). The Electron shim exports a default object so `electron-store` can bundle; without this, pack stayed on the 22 KB file/terminal-only Host and remote Chat hit `unknown method`.
- Host CJS pack now keeps `import.meta.url` (same rewrite desktop main already does). Without it, Pi’s `config.js` loaded as `fileURLToPath(undefined)` and every remote `agent:*` died with “path argument must be of type string … Received undefined” — including `listSessions` / `status` / `send`.
- Listing remote sessions no longer loads `node-pty`. Experiment-run still pulls the PTY executor when you actually run an experiment.
- Opening the app with a remembered remote project no longer logs security rejects or `fs:exists` / `agent:status` “Not connected” errors. `remote://` is not a local folder: the sidebar does not probe it on disk, and status / exists / file-tree scans return a quiet miss until SSH is up.
- `agent:status` no longer throws `undefined.on`: `attachOwner` was calling `EventEmitter.once` without binding `this`.
- Remote `literature:list` returns an empty library until RW-3 instead of throwing `literature_not_on_remote_yet` through IPC.
- Remembering a remote project no longer creates a `remote:` folder inside the app repo. Startup used the local “open folder” path, and Node’s `path.resolve` turned `remote://host/abs` into a relative `remote:/…` directory on disk.
- Remote Literature now talks to the Host library (`~/.prismnext/projects/<id>/library/` on the server). Opening a remote project lists that library instead of throwing `literature_not_on_remote_yet`. Zotero pull is still a later desktop-proxy step.
- Remote PDF extract and `literature-read-pdf` now run on the Host (pdfjs in the Host pack, or MinerU if the server has a token). The laptop does not silently parse a remote PDF. Missing both engines returns a stable `extract_parser_unavailable` error.
- Pulling a Zotero collection into a remote project now happens on this computer (local Zotero / Web API), then the Host writes the library and PDFs. The server never talks to the local Zotero app. Progress is `current / total / title`; Cancel is `remote:zoteroCancel`.
- Remote projects default to on-demand sync. The project menu can copy a file, a paper PDF, experiment artifacts, or chat sessions into `~/.prismnext/remote-cache/`. Files over 20 MB, `venv`, `node_modules`, and `.git/objects` stay on the server. Online-only turns off automatic session copies. The leftover live-mirror setting is treated as on-demand; that menu item is gone.
- If SSH blips, the Host process on the server stays up. This computer reconnects through a local forward to `127.0.0.1` and the connection panel shows Reconnecting, then Connected. A dropped stdio Host still means connect again.
- If another computer takes over the same Host, this computer shows that it was displaced — not that it is still connected.
- A packaged app missing the Host program says to reinstall PrismNext. The server does not download the Host program (only Node / Git / Tectonic), and there is no “pick a Host version” step.
- A missing OpenSSH `ssh` binary, or a failed ProxyJump / ProxyCommand, is named in the connection panel instead of a generic host error.
- Remote folder listings are cached briefly so the file tree does not re-walk the server on every focus change. Saves are still written immediately.
- Chat sessions on the server are the source of truth. This computer keeps a copy when a turn finishes, a chat is renamed, or one is deleted. If both sides changed, the server version wins and the older local file is renamed `*.local-conflict.json`. Offline, the sidebar can still open the cached transcript read-only.
- Remote TeX compile runs on the Host. The preview PDF is pulled in chunks to a temporary file on this computer — not into a full project mirror. If the server has no TeX engine, compile fails with a clear error.
- Experiments started on the server keep running if SSH drops. Reconnect and Job Monitor can attach and read the remaining log. The Host no longer claims that a dropped SSH kills the job.
- Pushing this computer’s user skills to the server is explicit (project menu). Remote Settings MCP lists read and write the project files on the server. Allow-always rules for a remote project are stored on the server.
- Opening a remote project no longer dies with `unknown method: literature:list` / `experiment:list`. Those methods are registered on the Host itself (not loaded later). An older Host on the server is treated as stale: disconnect and reconnect so this app can push the current runtime.
- Connecting no longer crashes the Host on handshake because listing literature/experiments pulled in `node-pty`. The Linux Host pack does not ship `pty.node`; PTY is loaded only when a run actually starts.
- The remote connect panel no longer clips the log to eight truncated lines. Steps show their detail, and the console wraps the full command and error text so a Host crash is readable.
- Remote Chat no longer dies with “No installed team with an enabled lead agent” after a clean connect. The Host payload now ships PrismNext Core (`resources/teams`) plus app slash commands, and the Host process is started with those paths — the server was previously scanning an empty folder.
- Remote Chat no longer pretends a missing Host key is “add a key in Settings.” Connecting now has a Model keys gate: this computer must actually send Settings → Models keys to the Host (provider ids only in the log). Saving keys while connected pushes them again. If the Host still has no key for the selected vendor, the error says so and tells you to reconnect.
- Connecting no longer fails the Model keys gate with `Cannot find module '../app/settings'`. The packaged main process is one file, so Settings keys are read through a normal import — not a relative `require` that only works in the TypeScript tree.
- Opening a remembered remote folder after SSH is up no longer dies with `fs:scanMetadata` / “No remote project is bound.” A live SSH pipe is not a project bind: `project:open`, the file-tree scan, and a successful connect all call Host `project.open` for the focused `remote://` folder.
- Host can `serve --listen 127.0.0.1:port` (localhost only). The desktop prefers that plus SSH `-L`, then `host.reattach` after a dropped control plane. `serve --stdio` stays the fallback. Directory-backed tests still use stdio.
