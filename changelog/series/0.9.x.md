## 0.9.0 (Unreleased)

### Remote

- Connecting pushes only the Host program (JS + Core teams + pin files). The Linux server then downloads official Node, portable Git, and Tectonic into `~/.prismnext-host/current/` and puts them on the Host PATH. You do not `apt install` them, and this computer does not ship those binaries in the PrismNext installer or over SSH. Experiment Python / venv is still the project’s own environment. The server must be able to reach nodejs.org and GitHub — the same network remote Chat already needs.
- Launch restore remembers a remote project path and its chats, but does **not** SSH on startup. Connecting on open made the app feel stuck. Reconnect stays a later, explicit action.
- The terminal on this computer now opens at the panel size (not a hardcoded 80×24), so Python / rich / progress bars wrap correctly before any remote is involved. Remote terminal is a real TTY via `/dev/ptmx` on the server — it does not require python3. The tab is labeled `bash · 远程`.
- Remote Chat can use Pro teams when this computer has an active Pro license. Connecting pushes Pro packs to `~/.prismnext-host/pro-package/` (not the public Host tarball) and sends a session grant **without** the activation key. After the packs land, Host writes install records for those team ids — discovery alone left them as `not-installed`, so remote Chat could not run Idea Arena. The Host ignores leftover `license.json` on the server. Clearing or expiring Pro on this computer revokes the grant on the live Host; disconnect does the same. The activity-team picker is the **same list** as a local project (Core / Pro / 通用团队). Switching the remote active team writes only the team id into that folder’s `teams.json` on the Host. After a Host payload push, a still-running listen process is killed when `stamp.json` changes so the new runtime actually loads.


- Remote hosts are read from this computer’s `~/.ssh/config` (including `Include`). You do not fill host / user / key in Settings. Open the Workbench add-project menu to see the list and connect.
- Connection uses the system `ssh` / `scp` already on your PATH, so ProxyJump, ssh-agent, and your existing keys work the same as in a terminal. A first-time host key is confirmed in the connection panel, then written to `~/.ssh/known_hosts`.
- The first successful connect still pushes this app’s Host program from the notebook (stamp = app version + checksum). A missing local payload fails locally. Node, Git, and Tectonic are downloaded on the server from those pins.
- Remote Workspace is a core capability: connect, Host, and remote Chat do not require a Pro license. The host list comes from `~/.ssh/config`.
- Chat’s Local / worktree control is unchanged — it is still the git checkout switch, not the remote-machine switch. Creating or switching a worktree on a remote project now runs on the Host: checkout lands in the server’s `~/.prismnext/projects/<id>/worktrees/`, and the app keeps talking to it as `remote://…`. Host file ops and the remote terminal may use that hangar for the bound project (not another project’s, and not `/etc`). Chat’s worktree cwd is the checkout, not the paper root.
- First connect after SSH succeeds no longer dies with “could not resolve remote $HOME”: the system `ssh` command is sent as one script, so `$HOME` is expanded on the server.
- Connect now keeps a constitution: each gate (payload, SSH, host key, home, push, Node, host process, handshake, doctor) is logged and shown in a dedicated connection panel, not inline in the Workbench add menu. License is not a connect gate.
- Connecting no longer requires Node on the server PATH. After the Host program lands, the server downloads a dedicated Linux Node 24 LTS into `current/bin/node` and starts `prismnext-host` with that binary.
- After a host is connected, the Workbench add menu opens a second-level list for that machine: recent remote projects, Open Folder, and New Project. Connecting does not open `$HOME` as a project; you pick a folder first. The file tree and editor talk to that folder over SSH. The sidebar marks those projects as Remote.
- Remote Chat now runs on the Host: send / stop / sessions / permissions go over SSH. The Host calls the model vendor directly. Connecting seeds API keys from Settings → AI; the server stores them as AES-256-GCM ciphertext in `~/.prismnext/host-model.json` (0600). The unwrap key stays on this computer (`safeStorage`). The laptop Gateway is an opt-in fallback when the server cannot reach the vendor. Chat UI is unchanged.
- Small laptop attachments (≤5 MB) are copied into the remote project’s `.workbench/uploads/` before the turn starts. Larger files are refused with a toast.
- Literature, LaTeX, and Interaction tools on a remote project fail with a clear “not on remote yet” error until the next phase. Experiment runs on the server, and say so if SSH drops.

### Developer

- `pnpm host:pack` ships a slim `prismnext-host.tar.gz` (Host JS, Core teams, `bin/install-runtime`, pin files). It does not download or embed Node / Git / Tectonic. Pins live in `scripts/host/node-version.txt`, `scripts/host/git-version.txt`, and `scripts/host/tectonic-linux.txt`. On connect, the server runs `install-runtime` (checksummed HTTPS). Host `main` prepends those bins to PATH; the SSH listen/stdio launch no longer inlines PATH. Git panel methods (`git:*`) and worktree methods (`worktree:*`) route to the Host for `remote://` projects. Returned worktree checkout paths are encoded as `remote://` so the file tree, Git panel, and Chat stay on the server checkout. Host FS containment allows the bound project’s worktree hangar; `terminal:create` uses the requested `cwd` when it is inside paper or that hangar (`toHostFsParams` now strips `cwd` / `projectRoot`).

- New `src/shared/remote` contracts (`ProjectHandle`, SSH frames, Host handshake, `SshConfigHost`) and a `prismnext-host` control-plane binary (`doctor`, `serve --stdio`) packed with `pnpm host:pack` into `out/host/` / extraResources. Transport default is system OpenSSH; the unused `ssh2` / `@types/ssh2` packages were removed. Remote Workspace is not a Pro entitlement (`workspace.remote` / `agent.remote` were never shipped). Default model path is remote BYOK (`host-model.json`); Gateway allowlist (still derived from `PI_PROVIDERS` plus user `aiBaseUrls`) is opt-in. The turn carries `provider` / `modelId` / `permissionMode`.
- Host payload filename is the arch-independent `prismnext-host.tar.gz`. Connect still reads remote `uname -m` so the server downloads the matching Linux Node / Git / Tectonic.
- Host pack now includes the Pi Agent (`agent:*`, ~18.5 MB JS). The Electron shim exports a default object so `electron-store` can bundle; without this, pack stayed on the 22 KB file/terminal-only Host and remote Chat hit `unknown method`.
- Host CJS pack now keeps `import.meta.url` (same rewrite desktop main already does). Without it, Pi’s `config.js` loaded as `fileURLToPath(undefined)` and every remote `agent:*` died with “path argument must be of type string … Received undefined” — including `listSessions` / `status` / `send`.
- Listing remote sessions no longer loads `node-pty`. Experiment-run still pulls the PTY executor when you actually run an experiment.
- Opening the app with a remembered remote project no longer logs security rejects or `fs:exists` / `agent:status` “Not connected” errors. `remote://` is not a local folder: the sidebar does not probe it on disk, and status / exists / file-tree scans return a quiet miss until SSH is up.
- `agent:status` no longer throws `undefined.on`: `attachOwner` was calling `EventEmitter.once` without binding `this`.
- Remote `literature:list` returns an empty library until RW-3 instead of throwing `literature_not_on_remote_yet` through IPC.
- Remembering a remote project no longer creates a `remote:` folder inside the app repo. Startup used the local “open folder” path, and Node’s `path.resolve` turned `remote://host/abs` into a relative `remote:/…` directory on disk.
- Remote Literature now talks to the Host library (`~/.prismnext/projects/<id>/library/` on the server). Opening a remote project lists that library instead of throwing `literature_not_on_remote_yet`. Zotero pull is still a later desktop-proxy step.
- Remote PDF extract and `literature-read-pdf` now run on the Host (pdfjs in the Host pack, or MinerU if the server has a token). The laptop does not silently parse a remote PDF. Missing both engines returns a stable `extract_parser_unavailable` error.
- Pulling a Zotero collection into a remote project now happens on this computer (local Zotero / Web API), then the Host writes the library and PDFs. The server never talks to the local Zotero app. Progress is `current / total / title`; Cancel is `remote:zoteroCancel`.
- Remote projects default to on-demand sync. The project menu can copy a file, a paper PDF, experiment artifacts, or chat sessions into `~/.prismnext/remote-cache/`. Files over 20 MB, `venv`, `node_modules`, and `.git/objects` stay on the server. Online-only turns off automatic session copies. The leftover live-mirror setting is treated as on-demand; that menu item is gone.
- If SSH blips, the Host process on the server stays up. This computer reconnects through a local forward to `127.0.0.1` and the connection panel shows Reconnecting, then Connected. A dropped stdio Host still means connect again.
- If another computer takes over the same Host, this computer shows that it was displaced — not that it is still connected.
- A packaged app missing the Host program says to reinstall PrismNext. The server does not download the Host program (only Node / Git / Tectonic), and there is no “pick a Host version” step.
- A missing OpenSSH `ssh` binary, or a failed ProxyJump / ProxyCommand, is named in the connection panel instead of a generic host error.
- Remote folder listings are cached briefly so the file tree does not re-walk the server on every focus change. Saves are still written immediately.
- Chat sessions on the server are the source of truth. This computer keeps a copy when a turn finishes, a chat is renamed, or one is deleted. If both sides changed, the server version wins and the older local file is renamed `*.local-conflict.json`. Offline, the sidebar can still open the cached transcript read-only.
- Remote TeX compile runs on the Host. The preview PDF is pulled in chunks to a temporary file on this computer — not into a full project mirror. If the server has no TeX engine, compile fails with a clear error.
- Experiments started on the server keep running if SSH drops. Reconnect and Job Monitor can attach and read the remaining log. The Host no longer claims that a dropped SSH kills the job.
- Pushing this computer’s user skills to the server is explicit (project menu). Remote Settings MCP lists read and write the project files on the server. Allow-always rules for a remote project are stored on the server.
- Opening a remote project no longer dies with `unknown method: literature:list` / `experiment:list`. Those methods are registered on the Host itself (not loaded later). An older Host on the server is treated as stale: disconnect and reconnect so this app can push the current runtime.
- Connecting no longer crashes the Host on handshake because listing literature/experiments pulled in `node-pty`. The Linux Host pack does not ship `pty.node`; PTY is loaded only when a run actually starts.
- The remote connect panel no longer clips the log to eight truncated lines. Steps show their detail, and the console wraps the full command and error text so a Host crash is readable.
- Remote Chat no longer dies with “No installed team with an enabled lead agent” after a clean connect. The Host payload now ships PrismNext Core (`resources/teams`) plus app slash commands, and the Host process is started with those paths — the server was previously scanning an empty folder.
- Remote Chat no longer pretends a missing Host key is “add a key in Settings.” Connecting now has a Model keys gate: this computer must actually send Settings → Models keys to the Host (provider ids only in the log). Saving keys while connected pushes them again. If the Host still has no key for the selected vendor, the error says so and tells you to reconnect.
- Connecting no longer fails the Model keys gate with `Cannot find module '../app/settings'`. The packaged main process is one file, so Settings keys are read through a normal import — not a relative `require` that only works in the TypeScript tree.
- Opening a remembered remote folder after SSH is up no longer dies with `fs:scanMetadata` / “No remote project is bound.” A live SSH pipe is not a project bind: `project:open`, the file-tree scan, and a successful connect all call Host `project.open` for the focused `remote://` folder.
- Host can `serve --listen 127.0.0.1:port` (localhost only). The desktop prefers that plus SSH `-L`, then `host.reattach` after a dropped control plane. `serve --stdio` stays the fallback. Directory-backed tests still use stdio.
