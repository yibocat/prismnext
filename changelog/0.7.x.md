# Changelog — 0.7.x series

## 0.7.2 — 2026-08-15

### Browser
- Maximized Browser tabs fill the RightArea again. The floating AiBar no longer leaves a large empty strip under the page.
- The in-app webview now follows the settled panel size and ignores tiny intermediate bounds while RightArea opens or restores.

## 0.7.1 — 2026-08-15

### Release verification
- Stable unified builds now provision and prewarm the bundled Tectonic engine in the verification runner before running the real bibliography and standalone-figure compiler tests.
- The stable test gate no longer falls back to an unavailable system `xelatex`; successful releases can publish the stable installer metadata that powers the download site.

## 0.7.0 — 2026-08-15

First stable of the 0.7 line. A team is now the unit of work, the official download is one installer, and chat bash shares a job identity with experiment runs. Existing 0.6 installs keep the same app identity and can upgrade in place. The public website follows this stable feed.

### Teams
- A team is one lead plus subagents, skills, commands, and MCP. Teams are app-level or project-level; the project can override the app (on / off / follow).
- Opening an older project migrates `packs.json` and `.prismnext/agent/local/` to `teams.json` and `teams/project.local/` once. Repeat opens do not migrate twice.
- Common Team and Project Team are always-on hangars. PrismNext Core can be disabled or uninstalled; Common Team remains the fallback lead.
- Settings → Teams is one hub (Teams / Skills / Commands / MCP). Composer switches the active team; that choice is who answers.
- Skills, commands, and MCP belong to a team. Composer `/` is app commands plus the active team’s roster. Locked Pro teams stay locked until a license is present.

### Pro
- The official installer includes Pro capabilities. A license unlocks them in the same app; there is no separate Free package.
- About accepts the early-access test key `PRISM-PRO-DEV-TEST`. Free features stay unlocked without a key. Settings → Pro → Hello is DEV-only.
- Activating or clearing a license reloads the Team catalog immediately. Chat tabs pinned to a now-locked Pro team drop that override.

### Welcome and jobs
- Welcome is two columns: Recent Projects on the right, New / Open on the left. New Project is an inline pane; Open Existing accepts a dropped folder.
- Chat bash and experiment runs share one `executionId`. Cards open a read-only Job Monitor; closing the monitor leaves the job running. Restarting the app reloads history; a job still running at quit is marked lost.

### Stability
- The file watcher follows only the opened project. Chat file links stay inside the project.
- The app-wide default team cannot be a project team. An empty new project no longer reloads MCP on first open.
- First chat after open can use a prewarmed project runtime. Writing system or expert files no longer restarts OpenCode after every turn.
- Task and subagent sessions link against the per-project runtime database.
- Windows OpenCode is a real `opencode.exe`. Window controls sit at the far top-right. The macOS menu extra shows a live agent count.

### Distribution
- A public Host `v*` tag dispatches the private build, which injects Pro, verifies, publishes the installer, and creates the GitHub Release. Beta and stable use separate feeds. This release updates the stable feed.

## 0.7.0-beta.4 — 2026-08-15

Verification cut of beta.3 so the unified installer can actually package. Still a test cut on `feature/open-core-pro-host`, not stable `0.7.0`. The public website stays on the stable feed.

## 0.7.0-beta.3 — 2026-08-15

Welcome workbench, one job identity for chat bash and experiment runs, and docs that name the 0.7 architecture. Still a test cut on `feature/open-core-pro-host`, not stable `0.7.0`.

### Welcome
- Two-column startup: Recent Projects on the right, New Project / Open Project on the left. Recent list is uncapped; hover reveals folder and remove. New Project is an inline pane; Open Existing accepts a dropped folder.
- Welcome re-reads the Pro key from disk. The “Pro activated” toast appears only after you submit a valid key.

### Jobs
- Chat bash and experiment runs share one `executionId`. Cards open a read-only Job Monitor on that job; closing the monitor leaves it running. Closing a chat stops only that chat’s bash jobs. Switching projects asks what to do with running experiments.
- Job Monitor toolbar: cancel, open a Shell at the job directory, copy the visible log. Restarting the app reloads job history; a job still running at quit is marked lost.

### Shell
- macOS menu extra is a rounded square with a live agent count; clicks open on mouse-down.
- Windows OpenCode package is a real `opencode.exe` (fixes `spawn UNKNOWN`). Window controls use standard Minimize / Maximize / Close and sit at the far top-right.

### Docs
- README and the download site describe Teams v2, the job plane, and one official installer. Pro lists all eight specialty teams; Early Access activation is documented for official builds that include Pro.

## 0.7.0-beta.2 — 2026-08-14

### Unified distribution

- **One PrismNext download** — the official installer now contains Pro capabilities alongside free features. A license unlocks Pro in the same app; the download site does not split users into Free and Pro packages.
- **Automatic private build** — a new public Host tag immediately dispatches the private build repository, which pins that exact commit, injects Pro, verifies it, publishes the official installer and creates the public release. Public CI never receives Pro source or R2 publishing credentials.
- **Safe update channels** — beta and stable builds use separate feeds. Stable unified builds retain PrismNext’s app identity and also update the legacy feed so existing installs can upgrade in place.
