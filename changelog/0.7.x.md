# Changelog — 0.7.x series

## 0.7.3 (Unreleased)

### Developer
- Type-checking now uses TypeScript 7 (native compiler). `pnpm typecheck` is the same command and should finish faster; running and packaging the app still go through Vite.
- Desktop build toolchain moved to Vite 7 and electron-vite 5 (React plugin 5). Vite 8 waits until electron-vite supports it. Node type definitions now follow Electron 43’s Node 24.
- Chat store file slices (`stores/chat/`) again pass `pnpm typecheck` after Phase 4 split — missing imports and composer mention types only; runtime behavior unchanged.

### Architecture
- Renderer stores must not import modes or components. Literature formatting, chat-turn helpers, experiment run queries, model preference keys, and composer draft helpers live under `lib/`.
- The chat store is still one `useChatStore`. Send, tabs, plan, and the composer queue live in `stores/chat/` files; the published names (`sendPrompt`, `loadSession`, `approveAndExecutePlan`) did not change.
- Renderer stores talk to the desktop through `lib/desktop-api/` (literature, extract, experiment, git, fs, project, workbench, execution, agent, research, settings, compile, terminal, log, commands, teams, MCP, browser, Pro license). Some Settings panels and leftover lib helpers may still call the bridge directly.
- Git orchestration and template apply flows now go through `lib/desktop-api/` (`git`, `template`, `fs`). Settings prompt/knowledge/rules/backup panels load through `lib/settings/` instead of calling the bridge from the component.
- Settings literature, workspace, general, teams list/create, commands, and MCP panels now go through store or `lib/desktop-api/` helpers. Research brief read/open and workspace folder autosave use the same ports.
- Settings Skills list, library, and SKILL.md editor now go through `lib/settings/skills.ts`. Slash-command catalog and “reveal in Finder” use the same skill and shell ports.
- Settings subagent and orchestrator editors now go through `lib/settings/subagents.ts`. Chat composer mention lists use the same subagent list.
- Settings provider editor (test connection / list models) and the system-font picker now go through `lib/providers` and `lib/theme`. Model catalog prefetch and effort lists use the same agent port.
- Settings About (version, check/download/install, legal links) and the sidebar update chip now go through `lib/updates` and the shell port. Shortcut labels read the host platform from the same shell helper.
- Settings team detail now goes through `lib/settings/teams.ts` (inventory, roster overrides, icon, install/uninstall). The shared teams store still owns the catalog list.
- Literature library helpers and the literature mode UI (PDF attach, reader, citations, Zotero bind) now go through `lib/desktop-api/` (`literature`, `extract`, `fs`, `agent`, shell). The literature store was already on that port.
- Experiments mode (create/edit from brief, compare, artifacts, provenance, registry-changed refresh) now goes through the experiment, fs, and research ports. The experiment store was already on that port.
- Template Center (list, preview, PDF, apply state in `.workbench/settings.json`) now goes through the template and fs ports. Apply-template flow was already on that port.
- Git mode commit detail, file diffs, and worktree-merge branch lookup now go through the git port. The git store was already on that port.
- Terminal mode (PTY create/write/resize, data/exit events, job cancel, clear/kill) now goes through the terminal and execution ports. The terminal store was already on that port.
- Switching the focused project only goes through `lib/workspace/project-lifecycle`. The file tree updates; chats from the previous project stay alive.
- RightArea tabs are a `kind` discriminated union. Mode and editor code narrows on `tab.kind` instead of a flat optional payload.
- Experiments Run in Ask mode uses the same permission card as chat. The private confirm modal is gone; 60s auto-deny stays on that shared card.
- Main-process code now lives in domain folders (literature, experiments, compile, git, and the rest) instead of a flat services drawer. Opening a library, compiling, or running an experiment still uses the same desktop commands.
- The literature library now lives at `src/main/literature/` (same level as agent and workbench). Callers import the facade or the domain file; the old flat `services/literature-*.ts` leftovers and the nested `services/literature/` tree are gone. PDF protocol registration stays in the app host; the domain no longer imports Electron.
- Catalog lookup (Crossref, arXiv, OpenAlex, and the rest) now runs in the main process. Shared bibliographic-metadata keeps parsers and types only — it no longer talks to the network.
- Main-process `lib/` no longer imports `services/`. TeX engine / bib-tool detection lives in `lib/tex-detect`; workspace folder reads used by bib-path resolution live in `lib/workspace-dirs`.
- Experiments now live at `src/main/experiment/` (registry CRUD, runs, venv gate, executor, provenance). The old `services/experiment-log-service.ts` monolith is gone; the domain no longer imports Electron.
- LaTeX compile now lives at `src/main/compile/` (orchestrate, Tectonic daemon, manuscript export). Engine detection stays in `lib/tex-detect`; the compile domain no longer imports Electron.
- Git CLI operations now live at `src/main/git/` (exec, status, stage, branch, log, merge, commit, worktree). Shared git types stay in `src/shared/git/`; IPC channel files stay in `ipc/git.ts`.
- Terminal (PTY, bash jobs, execution registry) now lives at `src/main/terminal/`. Project filesystem, workspace folders, and lifecycle authority now live at `src/main/project/`.
- Session sidecars (chat registry, display/context stores, citation appendices, composer attachments, project prewarm) now live at `src/main/session/`. Skills install/sync/registry live at `src/main/skills/`. Research plan/brief and interaction specs live at `src/main/research/` and `src/main/interaction/`.
- Team leftovers (install store, license, user teams, subagents sync, pro discovery, project MCP defaults) now live in `src/main/teams/`. Task-orchestrator gate and vision fallback live in `src/main/agent/`. The provider-chat HTTP helper lives in `src/main/lib/` so the literature domain does not import agent. Rules/prompt sync live in `src/main/prompts/`.
- Host shell leftovers (settings, tray, desktop notifications, update checker, glass vibrancy, system fonts) now live in `src/main/app/`. The flat `src/main/services/` drawer has no TypeScript sources left.
- File, folder-picker, new-project, and manuscript-template IPC now live in four channel-family files (`ipc/fs.ts`, `ipc/dialog.ts`, `ipc/project-scaffold.ts`, `ipc/template.ts`). The channel strings are unchanged — opening a folder, creating a project, and applying a template still use the same names.
- Literature, extract, Zotero, and bibliography IPC handlers now call `literature/host` (plus native dialogs). Progress still goes to the window that started the download; the channel names are unchanged. Domain tests keep importing `literature/facade` so they do not load the desktop settings store.
- The desktop bridge is split by domain (`src/preload/fs.ts`, `literature.ts`, `agent.ts`, and the rest). `electronAPI` method names are unchanged — after this update, quit and reopen the app so preload reloads.
- Literature, experiment, and git stores now talk to the desktop through `lib/desktop-api/` instead of calling `window.electronAPI` directly. Chat still uses the bridge as before.
- Shared contracts no longer pretend to be main-process services. `@shared/*` now resolves only to `src/shared/`. Permission modes, log types, tool catalog, workspace folders, and command types live in shared; the renderer no longer imports main through an alias.
- Literature, citation-health, extract, citation-network, and git/worktree payloads now have one TypeScript source in `src/shared/`. Settings and the renderer no longer keep a second copy of those shapes. The conversation reducer lives in shared so main and the UI project the same event stream.
- Shared contracts now live in domain folders (permissions, literature, agent, workbench, and the rest). Disk checks for interaction plots and figures moved out of shared into the main process. The leftover one-line re-export files at the shared root are gone — imports use the domain path.

### Workbench
- The sidebar is now a workbench: projects you open stay listed, each with its own chats underneath. Switching to another project's chat changes the file tree, library, and TeX/experiment panels — it does not kill the previous project's agent or wipe its conversation. Opening a folder joins the workbench (reusing its id when `.workbench/workbench.json` is still there). Removing a project from the workbench leaves the folder and chats on disk; the default project cannot be removed.
- A background chat that needs approval no longer steals you away from the paper you are in. The sidebar marks that row; a chip in the title bar names the project that is waiting. Click the chip (or the row) to go approve it. You can stop a background chat from its sidebar row — there is no “stop everything”. The title-bar chip no longer infinite-loops React on launch (it was treating an empty pending list as a new state every render).
- The environment / Welcome page is gone. Opening the app lands on a real default project at `Documents/PrismNext` (created if needed). Changing the default in Settings is a role change — it does not move the old project's files or chats. You cannot close the last project back to an empty shell.
- Approving a permission (or answering a question) in one chat tab no longer misses when another tab is also waiting. Each conversation keeps its own permission and question host. Stop without a conversation id is a no-op.
- New and newly opened folders get a `.workbench/` project config (id, workspace layout, compile cache). The app no longer writes a project-side `.prismnext/` for that. `workbench.json` can be committed; compile output lives in `.workbench/compile/` and is gitignored. An old `.prismnext/` next to the paper is left alone.
- Chat sessions now live in `~/.prismnext/sessions/`, not Application Support. Conversations stored in the old place are no longer listed. The app no longer reopens last time's project on launch — you land on the default project.
- Each project's literature library now lives under `~/.prismnext/projects/<id>/library/`, not next to the paper. Switching projects switches libraries. Adding a PDF in one project does not show up in another. Old project-side `.prismnext/library/` is not read or copied. Zotero still uses one app account and writes into the focused project's library.
- Custom skills now live in `~/.prismnext/skills/` and user teams in `~/.prismnext/teams/`. Turning a team off in Settings applies to every project. Creating a skill no longer writes `project.local/skills` into the paper folder. Open a new chat after you add or edit a skill.
- Agent worktrees now check out under `~/.prismnext/projects/<id>/worktrees/<name>/checkout`, not next to the paper. A worktree chat is still a session under that project — not a new sidebar row. Browser bookmarks and recent visits are one app-wide list in `~/.prismnext/browser/`; cookies stay in the existing Chromium partition. Old `.prismnext/worktrees/` and project-side browser folders are not read or copied.
- The leftover Welcome / environment page is gone from the app tree. Opening a project no longer writes `lastProjectPath` for auto-open. Stop or dispose without a conversation id is a no-op, so it cannot wipe every live chat. The host no longer writes OpenCode agent files under Application Support or `_prism-system.md` into the paper folder.
- The left sidebar is the workbench tree. There is no “current project” dropdown at the top. Projects are folders: click to expand their chats. Click a chat to switch the paper on the right. Add a project from the Workbench “+”; a hover “+” on a folder starts a chat in that project.
- Opening a folder no longer plants an empty `project.local` team under the paper. Settings → Prompts now opens `.workbench/agent/AGENTS.md` — the same file the agent reads. Creating a project team or saving project MCP still writes that hangar when you ask for it.
- Experiments, interactions, project rules, provenance, terminal config, research plans, and session sidecars now live under `.workbench/` (venv at `.workbench/.venv/`). An old paper-side `.prismnext/` next to the manuscript is not read or copied.
- Opening a worktree checkout joins the paper project — the app uses the folder that `openFolder` actually opened, instead of guessing the last project in the list. MCP tools and delegated experts in that chat run in the checkout, same as the main session. Switching papers no longer has a leftover “wipe every chat” path.
- Opening an old paper no longer converts leftover `.prismnext/agent/packs.json` or Local Pack files into `.workbench/`. Settings copy no longer mentions `_prism-system.md` or a project-side `.prismnext`. The leftover `lastProjectPath` electron-store key is dropped on read.

### Runtime
- Agent research tools no longer keep a leftover OpenCode file-bridge poller in the app tree. Chat still calls the same literature, experiment, LaTeX, and interaction functions on the Pi host.
- Session citation staging now lives next to the chat under `~/.prismnext/sessions/<conversationId>/citations/`, not in leftover Application Support OpenCode bridge folders.
- Agent bash jobs no longer write leftover result files under Application Support. Job Monitor still follows the same execution list.
- Enabled team skill folders are readable host roots, not project-escape. `read` / `ls` / `grep` / `find` resolve paths such as `library/catalog.json` against the skill that owns them; bash may list or cat those files. Copying or editing the skill folder is still blocked — copy into the project with `read` then `write`.
- Upgraded desktop shell to Electron 43 (Chromium 150, Node 24.18), updating the embedded runtime and native terminal bridges.
- New Agent now uses the embedded Pi runtime exclusively through the product `agent:*` API. Send, cancel, events, permission decisions, history list/load, and rename no longer branch to OpenCode/ACP.
- Conversation history is the Pi session store. Opening a past Agent chat continues that Pi conversation instead of spawning OpenCode. Old OpenCode transcripts are no longer listed or resumed through ACP.
- Agent events now project through the runtime-neutral Conversation reducer, preserving text that arrives after tool calls instead of splitting or overwriting the reply.
- The leftover DEV-only New Pi Agent entry, experimental banner, and `pi-lab` product protocol are gone.
- The Pi host now keeps Pi’s own file and shell tools (read, write, edit, bash, grep, find, ls) and wraps them with PermissionGate. Research tools stay as host add-ons. Asking a question or suggesting Plan waits for you instead of silently succeeding. Deleting a chat from the sidebar removes the Pi session, not an OpenCode transcript.
- Chat bubbles now read the Conversation document (turns and the live turn) instead of flattening Agent events back into the old OpenCode message list. Tool cards can show results while a turn is still running. Asking a question or suggesting Plan uses the Agent APIs. The welcome Agent status reflects the embedded Pi host, not an OpenCode subprocess.
- Settings now tests API keys, fetches model lists, and reads thinking-effort options through the Pi host. Those requests no longer go through OpenCode or its cached models.json.
- Project skills are injected into the Pi session from team skill folders. Creating or editing a skill no longer writes OpenCode config or `_prism-system.md`. The system prompt is composed in memory. Open a new chat after changing skills.
- Compress context now calls the live Pi session instead of sending `/compact` to OpenCode. Image descriptions for text-only models use the Agent API; the helper itself was already a direct provider call.
- Closing a project, rolling back a turn, Plan cards, intensive-reading sync, and worktree session re-homing now go through the Agent host. Asking a question no longer falls back to the old OpenCode file bridge.
- Team MCP servers now connect through the Pi host. Settings no longer reloads OpenCode when you edit mcp.json. Composer `/` an MCP on send attaches that server’s tools to the live conversation.
- Delegated team experts now run as Pi child sessions. The Task card and run panel show that child’s stream. Stop aborts the child instead of writing a fake OpenCode result. The parent bubble does not mix in the child’s text.
- Starting the app no longer launches OpenCode. Settings, team/skill refresh, and experiment runs no longer reload or query an ACP child. Product chat stays on the Pi host.
- The leftover OpenCode ACP service, `chat:*` IPC, OpenCode plugin tools, and the unused OpenCode event hook are removed from the app tree. Settings → Agent tools now lists the Pi host catalog.
- Provider configuration now lives entirely on the Pi catalog. Settings → Add Provider offers Pi’s providers (OpenAI, Anthropic, Google, DeepSeek, Moonshot/Kimi, Z.AI/GLM, MiniMax, Qwen, xAI, Groq, Mistral, OpenRouter, OpenCode Zen/Go and more) with model lists fetched live from the Pi runtime instead of hand-maintained presets or the OpenCode cache. Existing saved providers migrate to their Pi ids on first launch.
- The model picker hover card now shows the full Pi catalog metadata: context window, max output tokens, and USD per-1M-token prices (input/output), plus a fallback blurb when the catalog has no description. The context ring already uses the selected model’s Pi context window.
- The context ring now tracks the live Pi window and cumulative spend, with a Cursor-style category breakdown. Occupancy is the current prompt (it grows as the chat does, and no longer resets to this-turn billed input or to 0% mid-stream). The stacked bar is of the full window (1% used stays a thin sliver). Category sizes use the bundled js-tiktoken `o200k_base` encoder and are fitted to Pi’s occupancy total. Cumulative spend sits to the left of the ring (`< $0.01` when under a cent). Hover copy says “used”, not “full”. Segments become rounded pills with a small gap once the ring reads 5% or more.
- Removed the OpenCode provider/map/cache modules and renamed the remaining chat UI helpers to neutral names. Settings → About no longer probes a bundled OpenCode agent version.
- Composer `/` skills now actually load into the conversation: the skill ids you pick are forwarded to the Pi host, which pulls them into the session’s `<available_skills>` even when they are outside the current team roster.
- Delegated expert sessions (the Task tool) now inherit the team’s enabled skills and the subagent profile modules, so experts no longer run with a bare instructions file.
- Shell permission decisions now use one smart policy in both the renderer and the main process: harmless commands (e.g. `git status`, `pwd`) run without a prompt, commands on the deny list (e.g. `sudo`, whole-disk deletes) are refused outright, and everything else still asks you. The prompt preview and the actual gate can no longer disagree.
- Removed the OpenCode file-bridge permission polling (`bash-permission-bridge`) and the spike-era `createRepresentativeTools` / `createAgentExperimentRunner`; the experiment-run tool already owned that logic. OpenCode leftovers in permission type/function names were renamed (provider ids such as `opencode` are untouched).
- Model pickers no longer list the same model twice after adding a provider: the chat model dropdown, the multimodal-helper picker, and the subagent model picker deduplicate the Pi catalog against saved selection snapshots. Models that exist in both are shown once (catalog wins, custom-only entries still appear).
- Attached images now actually reach vision-capable chat models. Images were collected in the composer but dropped at the renderer→main IPC boundary, so the agent saw the text prompt only. Inline images now flow through `agent:send` into the Pi session, and text-only models keep using the multimodal-helper description path.
- Agent tools carry richer guidance again: native tools now expose `promptGuidelines` / `promptSnippet`, which Pi injects into the system prompt as usage rules. Literature, LaTeX, experiment, interaction, brief, and question/plan tools describe their prerequisites, boundaries, and return contracts instead of a bare one-liner.
- Removed the unused host-side `bash` tool definition (shell execution is a Pi primitive); the leftover experiment log, provenance, results snapshot, interaction, and LaTeX root tools also gained usage guidelines. Settings → Agent tools now shows each tool's guidelines alongside its description.
- Locale catalogs were split from one ~3.5k-line JSON per language into `locales/<lang>/<domain>.json` folders (22 files per language), aggregated at build time. Adding a new language is now just dropping a folder — no monolithic file to copy and edit.
- Plan mode works end to end on the Pi host again: accepting a plan suggestion now hands the model the canonical draft path plus a write binding, every Plan-mode turn appends the draft-file instruction, and PermissionGate applies the Plan overrides (edits only to the session draft, execution tools denied) regardless of the permission mode. OpenCode-era plan draft logic is reconnected to the Pi runtime.
- Chat message stability: late/stale Pi events no longer rebuild a ghost live turn (which hid the user bubble and stuck the composer in Stop); thinking and tool folds now carry real durations instead of "Thought for 0.1s" / "Worked for —"; a burst fold stays "Executing" while its tool is still running even after prose starts; the last turn stays in live-folding mode until the whole tab settles; and the 500ms end-of-turn fallback can no longer fail a rapid follow-up turn.
- A turn that goes silent (model stalled mid-thinking, provider rate-limited or network hung) now times out after 3 minutes with no events: the Pi runtime aborts the session and the chat shows "长时间未收到模型响应" instead of freezing on an empty "Thinking…" forever.
- Fixed the "tools ran but the final reply vanished" bug: Pi emits `turn_end` after every agent-loop turn including intermediate tool rounds, and PrismNext was treating each one as the end of the chat turn. That committed the turn before the model's final text arrived, so the reply's deltas were dropped as late. Only `agent_end` now closes the turn, so tool-call rounds stream their follow-up text and the final reply always renders.
- Chat messages now follow Pi's prompt / agent-loop model instead of the old OpenCode stream. Thinking and tool bursts keep the same fold tree from live to history (no whole-turn Worked-for remount), so a burst you expand stays open after the reply finishes. User bubbles, the Todo drawer, session titles, and citation backfill read the Conversation document. Approving a plan seeds the checklist on that turn; `/setup` actions report through toasts instead of fake stream rows.
- Shell tools no longer stall on “Please confirm above” with no buttons. The Allow / Deny card above the composer now reads the command from the Conversation (and the permission request itself), not the old OpenCode message list.
- Undo / rollback on a turn footer works again on the Pi chat path. It now counts Conversation turns instead of the leftover OpenCode message list (which stayed empty), and a failed engine undo restores the Conversation document instead of a blank transcript. File checkpoints start and finish with each Pi turn.
- Removed the leftover OpenCode chat/session preload surface (`chat:*` / `session:*` / `onChat*`). Those invokes had no main-process handlers and would hang if anything still called them. Startup no longer polls OpenCode file-bridge request folders; literature, LaTeX, experiment log, and related tools still run through the same service functions on the Pi host. Job Monitor follows Pi bash through the execution registry; the leftover terminal `request.json` poller is not started.
- Pi file-search and directory-list cards show what they are doing again. `find` and `ls` now use the same cards as glob/list, and the fold line takes the pattern or path from the tool arguments instead of waiting for an OpenCode ACP title (which Pi never sends). The result list unwraps Pi’s `{ content: [{ text }] }` payload, so a hit is no longer shown as “0 results”.
- Reopening a chat keeps the same fold tree as when the turn finished. Thinking, tools, and reply text are stored in the order they arrived, so two thinking stretches no longer get glued together at the top with every tool card shoved in the middle. Older chats without that timeline still open the previous way.
- The session list no longer shows the same chat twice after you reopen it. Reopening used to write a second save file with the same conversation id; that leftover file is removed, and the sidebar / command palette list one row per chat.
- Session citations fill again while the agent is still working. `literature-stage` now writes to the current chat id, and each successful stage lands in the Literature panel immediately instead of waiting for a tab switch that often never came.
- Approve & Build no longer drops a visible “The user approved the research plan…” bubble. The model still gets that instruction as a follow-up turn; the transcript stays on the plan and the next thinking block.
- Asking the agent to use a subagent no longer sends it hunting through `team.json` and `subagents/` folders. The live team roster is injected into the session prompt and the Task tool, so it should call Task with a listed expert id instead of discovering experts on disk.
- The Task run panel is back on the original float: `min(78vh, 780px)`, sitting above the composer (and on AiBar, in the same stack as the main chat panel). Switching to RightArea maximize no longer closes that panel or leaves AiBar idle.
- A finished Task that used to say the expert never attached now mounts the child’s stream (and the Task result text if the stream arrived late). Failed delegations — including an unknown expert id such as `general` — show as an error instead of a fake “done” with an empty panel.
- A Task that hits its time budget now reports `subagent_timeout` instead of `cancelled`, and the default budget is 60 minutes. Child activity also keeps the parent turn from being killed as idle.
- After the model says it will write, edit, or start a Task, the tool card appears as soon as the call starts streaming — you no longer wait on a blinking cursor while the file contents or Task brief are still being generated. The card leaves “Preparing…” as soon as the first argument arrives, and the child session starts warming in the background so the expert is not idle for the whole brief.
- Asking you a question stays on the composer (the card above the input), not folded into “Planning… question”. Each hang is one card: a new question no longer paints over an older unanswered tool, leftover questions in the transcript stay as one-line stubs, and the confirm card no longer sits there stuck on “Sending…”. RightArea maximize opens AiBar so the question is not floating over an empty dark pane.
- Tool cards and inline file links still open the matching RightArea surface when you click them. The agent no longer steals focus on every write, brief update, experiment start, or compile — a turn with many edits will not flicker the workspace. If TeX is already open, compile still refreshes the PDF in place. Adding a paper still refreshes the library list without switching away from chat.
- Images and files attached to a message are stored with that turn, so reopening the chat still shows them. Delegated Task runs keep the expert’s process (not only the parent summary) after a restart.
- Compress context still shortens the model’s window, and the chat now folds the compressed turns behind a single “show earlier” bar so the newer replies stay in place.
- Welcome and the context-ring copy no longer say usage comes from OpenCode. The command palette has an accessible description.
- Official installers no longer ship an OpenCode agent binary. Chat runs on the embedded Pi host; TeX still bundles Tectonic. A leftover developer `bin/opencode/` folder is unused and can be deleted.
- Settings copy no longer describes chat as going through OpenCode Task, ACP, or an OpenCode instruction file.
- Sending a message pins that turn to the top of the chat pane (the last turn is at least one viewport tall so the user bubble can sit at the top; the reply grows down). Long replies still follow the tail. The send queue floats over the transcript instead of shrinking the message pane.
- Switching models mid-chat now applies on the next send (the live Pi session is updated then). The context ring uses the new window as soon as you pick it; occupancy stays on the current prompt and spend keeps accumulating. If occupancy already exceeds the new window, a toast and the ring panel suggest compressing first — the send is not blocked and the prompt is not truncated.
- Compiling a standalone figure no longer goes through the TeX workspace article pipeline. Those files are not synced into `.workbench/compile/` or shown as the paper PDF.
- Agent compile of a standalone / TikZ figure now uses `latex-compile-standalone` (PDF next to the source). `latex-compile` is the paper pipeline only. The LaTeX workspace module no longer treats every compile request as a paper build, and bash is pointed at the matching tool instead of forcing figures onto `latex-compile`.
- In-project paper and figure compiles no longer hang for two minutes on a hidden permission prompt. The gate now uses the same smart policy as the composer card (allow in the project), so you do not wait for an Allow button that never appears.
- Chat shows compiled figures again: a PNG/PDF file chip or link in the reply is the picture (or a PDF peek), not only a path. After `latex-compile-standalone` (and paper compile) the PDF is auto-embedded if the model forgot the `artifact` fence — same fallback experiment runs already had.
- Same **file** no longer stacks as two file previews (PNG + PDF) in one reply — one preview per visual stem. Interaction is a separate reopenable object (chat card by id, RightArea panel); it is not a third file preview and does not hide a compile PDF. `interaction-write` still accepts sloppy specs (`figure:static`, JSON string, top-level `path`) and PDF, and returns a field-level error instead of a bare `invalid_spec`.
- Host tools can declare a product `outcome` (files or objects). Chat presents that once: compile PDF / declared experiment files as a preview or chip, a successful `interaction-write` as an Interaction card. The model does not have to write a fence for the product to show up.
- In-project bash runs without a command allowlist. The gate asks only for package installs and deletes, and still hard-blocks host-owned verbs (file `rm`, TeX engines, chat preview substitutes). Cwd outside the project still asks.
- Interaction cards no longer nest a second PDF file card inside the figure peek — the peek is just the page.
- Reopening a chat no longer dumps the agent-only “Referenced files” block into the user bubble. You see the line you typed.
- Scrolling up while a reply is still streaming stays put. The view only follows the tail if you are already at the bottom.
- Command palette (⌘K) mode items open the RightArea again. Choosing a Settings page while already in Settings switches the page instead of closing Settings.
- Browser’s empty page (and the guest canvas before a site paints) now uses the app background token, so it follows light and dark mode instead of staying white.
- The Browser address bar now suggests bookmarks, recent visits, a typed URL, and a search with the current engine. The list floats under the address field (same width), not as a full-width strip. Arrow keys move the highlight; Enter opens the selected row.
- Browser refresh reloads the current page and spins while it loads, including after a failed search. It no longer no-ops when the guest was torn down.
- Links inside a Browser page open again. Same-tab clicks stay in that tab; `target=_blank` / `window.open` open a new Browser tab. Electron 43 no longer emits the old `new-window` event, so those used to do nothing.
- Stopping a turn, or a turn that times out, no longer leaves the chat stuck: the next send used to fail with a raw `turn_in_progress` line in the bubble. Stop now releases that lock, and the message is readable.
- A vision chat model (for example MiniMax M3) now reads PNG/JPG itself. The multimodal helper `image-describe` is only offered to text-only models, so drawing a figure no longer turns into describe-the-picture plus `sips`/`gs` conversion. A compiled PDF is still a chat preview.
- A delete (or any other) permission prompt is part of the same turn as the tool call. The composer stays on Stop until you allow or deny; `agent_end` no longer closes the turn while PermissionGate is still waiting, and a finished turn no longer silently rejects that prompt.
- Drawing figures is now a closed skill path. Architecture: copy the TikZ template, edit nodes, `latex-compile-standalone`, stop. Data plots: copy the matplotlib template + style file, `experiment-run`, stop when PDF/PNG land. Observable Plot stops at the SVG. Putting a figure in the paper (`figure-pipeline`) or making a reopenable card (`figure-interaction`) runs only when you asked — drawing no longer probes the paper engine, converts formats, or wires the manuscript by default.
- TikZ drawing now starts from a shipped catalog: OpenTikZ templates and examples, plus PrismNext contract templates (transformer block, U-Net, diffusion, GNN, VAE, causal DAG, PRISMA flow, swimlane, timeline, tree, Venn) and the OpenTikZ ml/systems icons (GPU, dataset, attention, … — no brand logos). The agent copies the figure, edits only the template contract, and compiles standalone. Generic layered boxes, commutative diagrams, and small pgfplots stay as fallbacks. Data plots have named matplotlib patterns for CI bands, grouped bars, violin/box, scatter+fit, heatmaps, and ROC/PR — still copy the script + style, run, stop.
- Compile jobs and bash LaTeX hard-denies now show up in Settings → Application Logs (source, route, engine, success or fail). Sending a chat no longer writes a per-turn info line. Quitting flushes the last log lines to disk.
- Agent host boundaries now appear in Application Logs too: session create/open/dispose, compact, model switch, idle timeout, tool execute start/end, MCP connect, and Task subagent start/end. Logs stay at the layer that did the work — no chat text, tool arguments, or token deltas.
- Opening, switching, or closing a project now shows up in Application Logs, as do Git and worktree failures. A successful `git status` stays quiet.
- Experiment start/fail, a library that will not open, and a terminal session that cannot spawn now show up in Application Logs. The welcome status dot no longer writes a team-resolve info line every few seconds.
- Settings failing to save, and unexpected IPC handler crashes, now show up in Application Logs. Switching the default team no longer writes an info line. A handler that returns `{ ok: false }` is not treated as a crash.

- Application Logs no longer keep home folders or usernames: absolute paths are stored and shown as `…/filename`. Diagnostic messages are English. ## 0.7.0 — 2026-08-15

First stable of the 0.7 line. A team is now the unit of work, the official download is one installer, and chat bash shares a job identity with experiment runs. Existing 0.6 installs keep the same app identity and can upgrade in place. The public website follows this stable feed.

### Teams
- A team is one lead plus subagents, skills, commands, and MCP. Teams are app-level or project-level; the project can override the app (on / off / follow).
- Opening an older project migrates `packs.json` and `.prismnext/agent/local/` to `teams.json` and `teams/project.local/` once. Repeat opens do not migrate twice.
- Common Team and Project Team are always-on hangars. PrismNext Core can be disabled or uninstalled; Common Team remains the fallback lead.
- Settings → Teams is one hub (Teams / Skills / Commands / MCP). Composer switches the active team; that choice is who answers.
- Skills, commands, and MCP belong to a team. Composer `/` is app commands plus the active team’s roster. Locked Pro teams stay locked until a license is present.

### Pro
- The official installer includes Pro capabilities. A license unlocks them in the same app; there is no separate Free package.
- About accepts the early-access test key `PRISM-PRO-DEV-TEST`. Free features stay unlocked without a key. Settings → Pro → Hello is DEV-only.
- Activating or clearing a license reloads the Team catalog immediately. Chat tabs pinned to a now-locked Pro team drop that override.

### Welcome and jobs
- Welcome is two columns: Recent Projects on the right, New / Open on the left. New Project is an inline pane; Open Existing accepts a dropped folder.
- Chat bash and experiment runs share one `executionId`. Cards open a read-only Job Monitor; closing the monitor leaves the job running. Restarting the app reloads history; a job still running at quit is marked lost.

### Stability
- The file watcher follows only the opened project. Chat file links stay inside the project.
- The app-wide default team cannot be a project team. An empty new project no longer reloads MCP on first open.
- First chat after open can use a prewarmed project runtime. Writing system or expert files no longer restarts OpenCode after every turn.
- Task and subagent sessions link against the per-project runtime database.
- Windows OpenCode is a real `opencode.exe`. Window controls sit at the far top-right. The macOS menu extra shows a live agent count.

### Distribution
- A public Host `v*` tag dispatches the private build, which injects Pro, verifies, publishes the installer, and creates the GitHub Release. Beta and stable use separate feeds. This release updates the stable feed.
