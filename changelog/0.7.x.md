# Changelog — 0.7.x series

## 0.7.0-beta.2 (Unreleased)

### Unified distribution

- **One PrismNext download** — the official installer now contains Pro capabilities alongside free features. A license unlocks Pro in the same app; the download site does not split users into Free and Pro packages.
- **Automatic private build** — a new public Host tag is discovered by the private build repository, which pins that exact commit, injects Pro, verifies it, publishes the official installer and creates the public release. Public CI never receives Pro source or its release credentials.
- **Safe update channels** — beta and stable builds use separate feeds. Stable unified builds retain PrismNext’s app identity and also update the legacy feed so existing installs can upgrade in place.

## 0.7.0-beta.1 — 2026-08-13

First Pro-capable beta of the 0.7 line. The automated unified PrismNext delivery path arrives in beta.2. This is a test cut on `feature/open-core-pro-host`, not a stable `0.7.0`.

### What to try

- **Teams v2** — a team is one lead agent plus subagents, skills, commands, and MCP. Global teams survive switching projects; `project.local` stays in the repo. Switching the active team in Composer or Settings changes who answers.
- **Old projects migrate on open** — `packs.json` / `.prismnext/agent/local/` become `teams.json` / `teams/project.local/`. Repeat opens do not migrate twice.
- **Pro test key** — About accepts `PRISM-PRO-DEV-TEST`; Free features stay unlocked without a key. Settings → Pro → Hello is DEV-only (`pnpm dev:pro`), not in this packaged build.
- **Stability** — watchers and chat file links follow the opened project; the app-wide default team cannot be a project team; a brand-new empty project no longer reloads MCP/chat on first open.

Detailed notes for the eventual `0.7.0` remain under the Unreleased section below.

## 0.7.0 (Unreleased)

### Pro open-core

- **Pro Hello is DEV-only** — Settings → Pro → Hello and the register toast appear only in `pnpm dev:pro`; release / `dist:pro` builds no longer register the smoke page.
- **No duplicate Pro Hello toasts** — license hydrate / Pro module reload single-flight under React StrictMode; Hello toast fires at most once per process.
- **Early-test activation** — About points to the shared test key `PRISM-PRO-DEV-TEST` (no payment yet); Free features stay unlocked without a key.

### Stability

- **Project file watcher follows the opened project only** — scanning a folder no longer starts a watcher; authorization is committed only when the project actually opens in the UI. Failed or superseded opens restore the previous root (or revoke it). Switching or closing stops the previous watcher. Home-folder symlinks that point outside the user home are rejected.
- **Chat file links stay inside the project** — markdown file refs no longer open absolute paths, drive letters, or `..` traversal.
- **App default team cannot be a project team** — Settings no longer lets the app-wide default point at `project.local`.
- **Empty project no longer reloads MCP on first open** — seeding Project Team does not tear down the chat session.

### Teams v2 cutover fixes

- **Removed built-in free demo teams** — `MCP Demo Stack` (`prismnext.mcp-demo`) and `Research Notes` (`prismnext.research-notes`) no longer ship in the app catalog; specialty teams live in Pro. (The LaTeX **Research Notes** template is unchanged.)
- **Faster first chat after open project** — `chat:prewarm` pre-spawns the **project** OpenCode runtime while you are still in the editor; reopening the same project keeps that runtime (no dispose→respawn). Switching to another project still shuts down the previous ~170MB process. First-send UI shows clear stages; when prewarm already finished, send skips a duplicate experts/skills sync pass.
- **No OpenCode restart after every chat turn** — writing `_prism-system.md` / expert files no longer counts as a skills config change; skills reload only when `skills.paths` or skill permissions actually change (was stalling the UI right after the reply finished). The send path never reloads OpenCode — instructions are written to disk and picked up on the next spawn.
- **Task / subagent sessions link again on project chats** — child OpenCode sessions live in the per-project runtime DB; linking no longer falls back to the global `opencode-server` DB (which made Tasks look hung: `task-link-degraded` / `task-await-timeout` / `expert=@expert` while peers actually ran).
- **Teams browse cards are compact** — borderless two-column rows with icon, name, one-line description, and Install (or ⋯ for installed). Row hover uses `accent` (light) / `card` (dark); the ⋯ control uses `accent`. Installed rows open Manage / Uninstall. Detail actions (Install/Uninstall + Manage in Settings) sit in the header as compact `xs` outline buttons with icons, matching Settings page chrome.
- **Teams Center narrow layout** — detail hides the meta sidebar below `lg`, stacks actions under the title when the content column is tight, and keeps `min-w-0` / word-break so text no longer collapses into a one-word column.
- **Chat lead agent now follows the active team** (`teams.json`), not the legacy `packs.json` default — Settings “set active” and Composer team switch finally change who answers.
- **Composer active-team picker** — switch the team (lead agent) next to Plan/model controls; updates project default and the current tab. Shows team name only (lead name moved to tooltip). Only appears in the expanded AiBar and the panel toolbar; the narrow capsule hides it to keep the input area clear. Toast confirmation; app logs record `setActiveTeam` / `resolveChatOrchestrator` / `chat:send active lead`.
- **Active team stays in sync** — Composer switch writes `teams.json` (so new sessions keep the choice); Settings activate clears tab overrides; Teams Center install/uninstall force-refreshes the shared catalog so the Composer dropdown shows new teams immediately.
- **Settings Lead detail no longer “Orchestrator not found”** for Pro/installed teams — detail IPC resolves via the v2 TeamResolver (FQID), not the legacy catalog-only facade.
- **Team MCP merge works in packaged builds** — ACP no longer uses a broken relative `require` for the Teams resolver (was failing with `Cannot find module '../teams/resolver'`).
- **OpenCode restart coalescing** — concurrent skills + agents reloads no longer tear down ACP mid-handshake (`ACP connection closed` / experts-refresh deferred).
- **FS watcher watches `teams.json`** for agents sync (was only `packs.json`).
- App-level team install/uninstall now refreshes all registered open projects (not a no-op when `notifyTeamsChanged()` had no root).
- **Removed dual lifecycle** — dead `services/teams-lifecycle.ts` deleted; install/enable/uninstall tests target `teams/lifecycle` only.
- **Chat/facade judgment uses v2 only** — `subagents-sync` no longer imports legacy `team-resolver`; roster overrides resolve bare ids across teams.
- **M8/M11 on-disk migration** — opening a project moves `.prismnext/agent/local/` → `teams/project.local/` (FQID `project.local:…`) and converts `agent/mcp.json` into `project.local/mcp.json`; legacy files land in `legacy-backup-<date>/`.
- **Team switch actually changes who answers** — OpenCode 1.18 only accepts ACP `mode` (not `agent`); chat send now sets `mode=<team-lead>` after the session is hydrated. Settings “set active” clears Composer tab overrides so the picker stays in sync.

### Teams architecture v2

- **Team = one lead agent + subagents + skills + commands + MCPs.** A team carries at most one lead agent (orchestrator), enforced structurally by a singular `orchestrator/` directory. Capability-only teams (no lead agent) are supported.
- **Subagents belong to their birth team but can be referenced by any team's roster.** A lead agent's roster specifies which subagents it can delegate to — cross-team references are supported, cross-scope references are flagged with a way out (promote team / move asset).
- **App-level + project-level dual scope.** Teams are either global (app-level, shared across projects) or project-level (only in that project). Scope is a property of the team, never a separate UI control. The project level can override the app level (tri-state: on / off / follow global).
- **Single precedence table.** One table (project > user > registry > pro > bundled > core) drives runtime name resolution, skills.paths ordering, MCP name conflicts, and origin badges — no more four conflicting priority systems.
- **MCP as a first-class asset.** Team-provided MCP servers now appear in the slash command catalog and can be lazy-loaded (previously they were invisible to the composer). A new `autoStart` field enables eager connection at session creation.
- **BlockedHint on every disabled switch.** Any greyed-out toggle shows why (not installed / license / incompatible / team disabled / shadowed) and offers a way out (activate / enable team / follow global).
- **OverrideDot indicator.** When a project-level setting differs from the app-level, a "·overridden" indicator appears with a tooltip explaining the global value and a click-to-reset action (VSCode settings parity).
- **One-shot on-disk migration.** Existing projects' `packs.json` / `packs-installed.json` are automatically converted to the new `teams.json` / `teams-state.json` on first read. The migration is idempotent and atomic.
- **Unified Settings → Teams page.** Active team on top; one list card of team rows (scope / origin / enable). Click a row to open the right-side team detail (same panel as before). Lead and subagent rows in detail open their editor tabs; subagent list ends with **+** to add another team's subagent onto this lead's roster. Skills / Commands / MCP use flat `SETTINGS_CARD` lists (not grouped switches).
- **Settings → Teams hub** — sidebar keeps one Teams entry; page tabs switch Teams / Skills / Commands / MCP with a shared search that filters the active tab. Old category ids (`skills` / `commands` / `tools-mcp`) still open the matching tab.
- **Prompts & Rules → Preview stack summary** — shows all injection layers and total token estimate (not only `_prism-system`).
- **Prompts & Rules → Built-in modules / tools panels** — drop nested cards; flat sections with hairline dividers and a single content frame (aligned with lead-agent instructions).
- **Built-in teams can be uninstalled** from team detail (catalog files stay for Browse re-install). **PrismNext Core is optional** — default-installed, but users may disable or uninstall it freely.
- **Common Team (was “My Content” / “Common”) is the always-on safety net** — display name Common Team / 通用团队; id stays `user.my-content`. Ensures a Chat lead, cannot be disabled/uninstalled/deleted, and is the final active-team fallback when Core (or any other lead team) is off. Agent sync no longer hard-fails without an active lead (subagents still sync).
- **Common Team + 本项目团队 always appear in Settings → Teams list** — project hangar is seeded on project open (not only after first subagent/skill write). Neither hangar appears in the Teams store/browse.
- **Create team opens a right-panel form** — name, scope, descriptions, tags, and seed Lead name/instructions; custom teams stay local (not store/distribution).
- **Common Chat roster is own-team only (`$pack` → `@team`)** — does not inherit Core experts, and does not use empty allowlist (which hid newly created subagents from Task sync). Custom-team and project.local leads seed the same way so birth-team subagents appear on that lead’s syncable roster.
- **Left sidebar sessions show again for project runtimes** — `session:list` / load / delete / rename now read the per-project `opencode-runtimes/…` database (same place chat writes), not the global `opencode-server` store.
- **Settings → Teams UI cleanup** — removed the redundant Active Team block and list enable switches (enable lives only in detail); detail drops duplicate Browse; set-active / delete share one action row; user-created project teams can be deleted again (were blocked by a false “local” kind). Active badge updates live across list + detail.
- **Teams list contrast** — team names match other Settings row labels (not muted-by-default); hover only brightens text, no background fill.
- **Teams “Overridden” indicator** — only when the project enable flag actually differs from the effective global/default; project-scoped teams never show it (no app layer).
- **Teams list hangars section** — Common Team and Project Team sit in a separate Always-on hangars block below installed/created teams; hangar titles always follow the UI language (no more hard-coded Chinese on disk leaking into English UI).
- **Removed Teams page Reset** — leftover Core-subagent factory-reset control; no longer shown on Settings → Teams.
- **Skills follow the team allowlist (like subagents)** — auto-available skills are the active team’s own skills plus foreign ones added via team detail **+**; Composer `/` can still invoke other enabled skills for that turn. New skills pick a target team (default Project Team).
- **Settings → Skills lists all skills; enable switches only on hangar / user-owned copies** — Core and store-team skills are browse-only here (toggle via the owning team’s Skills **+** allowlist). Install library no longer mirrors Core as “prismnext Curated”; add GitHub/registry sources and install copies into Project / Common Team.
- **Settings → Skills flat list** — one card of rows (name · ~tokens · team · description); click row to open; self-owned skills can be deleted (no per-skill enable Switch).
- **Team detail Skills: Add / Install / New** — **Add** pulls pack skills onto the allowlist; **Install** opens the skill library (source → install); **New** creates a skill owned by this writable team.
- **skill-creator install path** — teaches writing skills to `.prismnext/agent/teams/project.local/skills/` (Project Team hangar), not the legacy flat `.prismnext/agent/skills/`.
- **MCP is team-owned** — sessions only load the active team’s MCP servers (no cross-team “+”). Settings → MCP is a flat list (name · team · transport); click to configure; no per-server Switch. Install (app-curated presets) / Add from JSON pick a writable team (Common / Project / custom); team detail MCP footer matches (no + / no duplicate New). **Edit team JSON** opens one writable team’s `mcp.json` via TeamPicker (not the whole list; pack/demo teams stay read-only from their own files). Removed the confusing “Apply to chats” button (saves already reload open sessions).
- **MCP install list refresh** — writing a team `mcp.json` invalidates the teams catalog/resolver cache, and Settings → MCP reloads as soon as install/paste/save finishes (no need to close the right panel first).
- **Curated MCP presets live in `resources/mcp/presets.json`** — edit that file to maintain the Install catalog (no longer hardcoded in TypeScript).
- **App-level slash commands leave Core team** — `/compact`, `/compile`, `/setup`, `/bib-check`, `/brief` live under `resources/commands/` (FQID `app:…`), not PrismNext Core. Always available in every chat; independent of Core install/enable. Removed unused `/undo` / `/redo` (rollback UI stays via the restore bar).
- **Team commands stay team-owned** — Project / Common / custom / Pro specialty commands use birth-team ownership + lead `allowedCommands` (**+**). Composer `/` = app commands ∪ active team roster.
- **Settings → Commands flat list** — rows show App vs team; click to open; self-owned deletable; no Import/Export. New commands pick Project / Common / custom via TeamPicker.
- **Team detail Commands: Add / New** — **Add** pulls another team’s command (not App); **New** creates under this writable team.
- **Settings → Teams list tags simplified** — quiet scope text (no icon pill); list shows Pro only when needed (bordered Pro chip); origin / Always on / Overridden leave the list; activate sits on the row’s right (button vs “Activated”); detail meta leads with publisher (no redundant Global/Pro chips); override-reset lives on the enable card.
- **Locked Pro teams in Settings** — no detail panel while license is missing; row offers Activate → About; duplicate “Pro” lock badge removed (shows “Requires Pro” instead); Set active hidden when locked.
- **PrismNext Core is no longer a special “Built-in” badge** — detail shows the same Official origin chip as other `resources/teams/` suites; uninstall/disable use the same copy (Common remains the always-on safety net).
- **Bundled teams migrated to the v2 on-disk layout** — `resources/teams/*` now use `team.json` + `subagents/` (no more shipped `plugin.json` / `experts/`). New packs author against this layout; scanner still accepts legacy plugin.json as fallback only.
- **Lead roster UX** — lead editor no longer checkboxes allowlists; team detail toggles own subagents (asset enable) and uses + only for external roster members.
- **Lead editor content frames** — instructions and synced roster previews use a bordered content box (no fill, min height, grows with content); roster drops the outer card chrome and “allowed x/y” summary.
- **Lead / subagent editor actions** — removed Save / Cancel / Reset defaults; changes auto-save. Built-in & store leads are read-only (no per-lead model — use Composer); Common Chat is locked. Custom leads auto-save but have no Delete (≤1 lead per team — delete the team instead); custom subagents keep Delete when removable, with a dedicated model override.
- **Custom team leads are undeletable** — Settings lead editor hides Delete for every lead; main-process delete refuses all lead removals so a team cannot lose its only lead.
- **No standalone “New lead”** — creating a custom team seeds its lead (`orchestrators/lead/`). New subagents default to Common (app hangar); `project.local` remains an explicit project hangar only.
- **New subagent uses an explicit Create button** — draft is not autosaved until created; later edits autosave. Slot mode `customize-builtin` renamed to `installed` (bundled / store / Pro).
- **project.local hangar** — seeds an undeletable Project lead (like Common Chat); team detail inventory passes `projectRoot` so project-scoped assets show up; writing into project.local invalidates the catalog. Project lead remains editable (Common Chat stays locked); fixed a bug where editing Project lead mistargeted Common Team and refused to save.
- **本项目团队 is always-on like Common** — detail shows “Always available” (no enable switch); cannot be disabled/deleted; always listed in Settings → Teams; re-clicking the row does not close its detail.
- **Deleting a custom subagent warns when other teams reference it** — confirmation lists those teams; confirm deletes the asset and strips it from their Task rosters. *(Follow-up: same referrer → confirm → purge flow for skills / commands / MCPs once their create/ownership UI is ready.)*

- **`user.local` → `project.local` FQID rewrite.** The legacy Local Pack's FQID prefix is rewritten to `project.local` in all state keys during migration.
