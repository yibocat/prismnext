## 0.6.5 — 2026-07-28

### Python environment

### Interaction — computed numbers, not guessed ones

- New shared compute layer (`$grid`/`$exprGrid`/`$exprSeries`/`$expr` expression markers) used by both `figure.plotly` and `instrument` — a formula-based figure's coordinates are evaluated exactly by the host, never hand-typed by the agent
- `figure.plotly` inline mode now accepts `model.domain` + `model.params` and resolves markers once at write time; the resulting real numbers are baked into the saved spec, so rendering stays untouched (no marker syntax at read time)
- Hard structural gate: for continuous-domain trace types (surface/mesh3d/contour/heatmap/cone/streamtube/isosurface/volume, and any lines-mode scatter), a literal hand-typed coordinate array is rejected outright — no size threshold, since a short array can be just as wrong as a long one. Real/interpolated data still goes through Python + `resources` as before; discrete/categorical data (bar/pie, markers-mode scatter) is unaffected
- New `$exprSeries` marker with a per-call `resolution` override enables coarse-to-fine step animations (e.g. a 5-frame slider from 3 to 50 sample points) without any literal arrays
- Fixed the app getting stuck on the splash screen after adding `figure.script`/`diagram.mermaid` validation — file-system checks were accidentally reachable from renderer (client) code; moved to main-process-only validation services
- `interaction-write` no longer returns opaque `invalid_spec`: missing `id`/`title`/`kind`/… get a field-level error + a full sample envelope; omitted `compute`/`revision` default to `local`/`1` on write (agents must not invent revision numbers)
- Expression dialect: `^` / `**` as power, `pi`/`e` aliases; rejected expressions name the unknown identifier (declare in model.params or spec.bindings)
- Instrument merges `model.params` and `spec.bindings` into one expression scope (no separate “where to put constants” rule)
- Interaction guidance now comes from one runtime capability contract: the prompt asks the agent to reason about data source, time behavior, and rendering needs; the actual synchronized tool describes only capabilities Prism really supports
- Formula domains can declare named axes (for example `theta`/`phi` or `x`), rather than relying on hidden `u`/`v`; existing artifacts using the old form remain readable
- Bound resources are fingerprinted when written. If an experiment output changes later, Prism asks the agent to rewrite the Interaction as a new revision instead of silently showing different data
- `instrument` now rejects any spec with zero `spec.bindings` — a surface with no adjustable parameter isn't an instrument, it's a static figure (use `figure.plotly`); this catches "adjustable surface has no sliders" at write time instead of shipping a dead widget
- The `question` tool now spells out that discrete-choice questions must pass each choice via `options` (not just listed in the prose), so multiple-choice prompts render as clickable options instead of silently degrading to free text

### Interaction (programmable canvas)

- Controlled canvas contract: Agent adapts domain objects; Prism hosts display channels (not a catalog of every scientific format)
- `figure.static` — show PNG/SVG (or sandboxed HTML) from `resources` (`role: figure` / `html`) so Python/professional exports open in RightArea
- `scene.program` — same-page host API (`ctx.el` / bindings / size / theme / resource / `ctx.three`); custom demos use artifact `scene.js` exporting `mount(ctx)` / `setup(ctx)`
- Built-in Lorenz attractor (`entry: builtin:lorenz`) remains an optional stock demo only
- Existing `plot.*` / `math.*` kept as declarative shortcuts; interaction-write + Interaction prompt document when to use each kind
- Fix agent-written `scene.js` load: do not `import(blob:…)` (Vite fails); evaluate mount/update/dispose in a CJS-like scope; bare `import` is rejected — use `await ctx.three.ensure()`
- Hard scene.program contract: Proxy `ctx` rejects invented keys (`canvas` / `THREE` / `params`); load-time bans for `import`/`require`; Interaction prompt includes a minimal legal `scene.js` sample
- Legacy Agent scene.js (`ctx.THREE` / `ctx.canvas` / `ctx.params`) no longer hard-fails: a compat shim maps them onto a dedicated canvas + THREE module so torus/sphere demos can run while prompts still push the real API
- Fix scene.program always showing Lorenz when Agent forgot `entry`: default/infer `scene.js`; accept `setup(ctx)` alias; **no silent Lorenz fallback** — missing scene.js shows a clear error until Agent writes the script
- `interaction-write` now accepts `sceneSource` and writes `scene.js` atomically with the spec; custom `scene.program` without a script is rejected at write time (with a legal sample), so Agents stop shipping `import` / spec-only scenes
- scene.js loader accepts `main` as a mount alias; write-time contract rejects invented `ctx.mount`/`ctx.frame`/`ctx.three.THREE` and requires an explicit mount/setup/main export
- Soften Interaction guidance: match the user’s subject with a new scene.js; no topic allowlists in prompts/tools
- Pause scene/math WebGL when the Interaction tab is inactive (RightPane keeps tabs mounted — background RAF was freezing the whole app)
- Legacy detection ignores comments; `ctx.three.ensure` forces the official path; reject `ensure().then((THREE)` and self-made `WebGLRenderer` with ensure
- Open Interaction tabs refetch when the same artifact is rewritten
- Hard-deny generic write/edit on host-managed Interaction files only (`artifacts/<id>/spec.json` and root `*.{js,mjs,cjs}`); nested sidecar resources stay writable; sceneSource is dry-run evaluated before disk write; successful write focuses the Interaction panel
- Soft-compat loader: strip common `three` ESM imports, remap `init`→`mount`, page-style WebGL/`OrbitControls` demos run via canvas shim; still prefer `await ctx.three.ensure()`
- Scene mount failures write `.last-error.json`; `interaction-read` returns `lastError` so the Agent can fix and rewrite `sceneSource`
- `ctx.three.ensure()` handle now exposes `root` / `dom` / `overlay` (host element) so Agent HUD overlays stop crashing on `appendChild` of undefined; canvas remains `renderer.domElement`
- **A/C stability:** scene.program is content+bindings only — hard-ban `createElement` / `innerHTML` / HUD `appendChild`; readouts via `ctx.setStatus`; formula surfaces/metrics default to `math.*` in prompts/tools (scene.program only for custom WebGL)
- Interaction prompt module is always injected (no longer profile-only) so kind routing reaches the Agent
- Clearer scene contract: wrap bare mount bodies; reject `const THREE = await ensure()`, `ctx.scene`, `ctx.onChange`, `ctx.spec` with fix-it messages
- **scene.ir (declarative 3D):** new kind with validated `spec.model` — parametric surface, probe, metric modes, wireframe/tangent/axes layers; host renders (no arbitrary JS). `interaction-write` rejects sceneSource; legacy `scene.program` scene.js no longer executes (migration message; `builtin:lorenz` only)
- Fix `math.*`/`scene.ir` expression evaluator: bare trig/math identifiers (`cos(u)`, `sqrt(u*u+v*v)`, `PI`) were allow-listed but not bound at eval time, so any formula not prefixed with `Math.` (e.g. sphere/torus/geodesic parametrizations) crashed with `ReferenceError: cos is not defined`. Also widened the safe-function set (`atan2`, `asin`/`acos`/`atan`, `sinh`/`cosh`/`tanh`, `log`/`log2`/`log10`, `hypot`, `cbrt`, `floor`/`ceil`/`round`/`sign`) needed for Riemannian-metric / Christoffel-symbol style formulas, and merged the allow-list + eval-binding into one source of truth so they can't drift apart again
- **scene.ir write preflight:** `interaction-write` now runs `buildSceneIr` with default bindings before publishing; compile failures return `phase: compile-preview` and leave the previous spec untouched
- **Atomic spec writes:** `spec.json` is written via temp file + rename to avoid half-written JSON on crash
- **Python figure lane (prompt):** Interaction module documents matplotlib/plotly → PNG/HTML under `.prismnext/artifacts/<id>/` → `figure.static` (sandboxed iframe for HTML); complements scene.ir for paper-grade charts Agent cannot express declaratively
- **figure.static write guard:** `interaction-write` rejects missing `resources[]` or PNG/HTML not yet on disk; artifact-relative filenames (e.g. `curvature_heatmap.png`) resolve under `.prismnext/artifacts/<id>/`
- **figure.static sandbox hardening:** agent-generated HTML gets a network-denying CSP injected before rendering (the `allow-scripts` iframe sandbox alone blocks DOM/cookie access but not outbound `fetch`/XHR); figures/HTML over 15MB are rejected with a clear error instead of hanging the panel; the HTML preview now times out (10s) and reports a load error instead of spinning forever
- **Interaction ↔ Experiment wiring (bound):** prompt + tool guidance now spell out the existing `experiment/<id>/results/...` passthrough — after a run already produced a chart/table, `interaction-write` should bind `compute: "bound"` resources straight at the real run path instead of copying into `.prismnext/artifacts/<id>/` or re-plotting with Python
- **Interaction module slimmed (~1300 → ~300 tokens):** moved all "how" content (scene.ir/figure.static JSON samples, Python venv recipe, self-contained-HTML rule, bound resource paths) into the `interaction-write` tool description; the always-injected prompt module now only carries the "which kind for which need" judgment table
- **scene.ir / math canvas framing:** stop auto-shifting meshes to the bounding-box center (that made axes look off-origin). Default is mathematical `(0,0,0)`; Spec can opt into `model.view.frame: "bbox"` or `orbitTarget: "probe"` / custom `camera`

### Interaction (Plotly runtime V1)

- **figure.plotly (new):** scientific 2D/3D now renders via plotly.js — Agent writes Plotly figure JSON (inline `spec.model.figure` or a `.json` resource), the panel opens with rotate/zoom/hover/legend for free; write is structurally validated first and returns a copyable sample on failure, render failures land in `.last-error.json` for the Agent to self-repair
- **Step-through demos for free:** figures that include `frames` (with `layout.sliders` / `updatemenus`) get slider-driven single-stepping and Play/Pause with no extra plumbing — useful for gradient-descent trajectories, time evolution, or any precomputed algorithm walkthrough
- **Renderer registry:** the Interaction panel now dispatches `kind → view` through a data table instead of an `if/else` chain; adding a future kind (graph/diagram/instrument) means adding a table row, not touching the panel component
- `scene.ir` / `math.*` / `scene.program` remain functional (unchanged) but are now documented as legacy — new work should prefer `figure.plotly`
- **Python authoring recipe (V2):** `interaction-write` now includes a matplotlib → Plotly quick-conversion map (scatter/bar/surface/contour/heatmap/vector-field) so Agent-authored Python figures target `figure.plotly` directly instead of exporting flat PNGs; the bound `experiment/<id>/results/*.json` passthrough and Python-shaped `frames`/`sliders`/unicode output are now covered by tests

### Interaction (instrument + host stepper, V3)

- **instrument (new):** a live-recompute sibling of `figure.plotly` — Agent authors a real Plotly figure template plus a handful of evaluation markers (`$grid`/`$exprGrid`/`$expr`/`$state`/`$stateTrail`); Prism resolves them against continuous `bindings` and re-renders via `Plotly.react` (no remount, no flicker) as sliders move
- **True step-by-step iteration:** `model.step.{init,next,max}` defines a real recurrence ($x_{n+1}=g(x_n)$-style) — the panel grows Prev/Next/Reset/Play controls automatically; every step is replayed from 0, so it's always reproducible and capped at a hard ceiling to prevent runaway loops (Newton's method, EM, BFS-style walkthroughs)
- Reuses the existing math expression sandbox and continuous-binding sliders (no new binding schema); plugs into the renderer registry by table entry, same as every other kind
- `scene.ir` / `math.surface` / `math.field` rendering is untouched in this pass — their Three.js hosts stay until the schema deprecation pass (V4), not deleted piecemeal

### Interaction (retire scene.ir / math.\* / scene.program, V4-A)

- **Legacy kinds retired:** `scene.ir`, `math.surface`, `math.field`, and `scene.program` are no longer accepted by `interaction-write` — the Agent gets a clear message pointing at `figure.plotly` (2D/3D) or `instrument` (live recompute / step iteration) instead of a generic "unsupported kind"
- **Existing artifacts stay readable:** opening a previously-created `scene.ir`/`math.*`/`scene.program` artifact shows a read-only migration card (with the saved model JSON for reference) instead of a blank panel or crash — no silent failure for work created before this change
- **~2800 lines of Three.js rendering code removed:** the whole custom scene/math renderer stack (`scene-ir-host`, `math-three-host`, `interaction-scene-ir`, `interaction-scene-contract`, the programmable-canvas scaffolding, and their views) is gone; the shared math expression sandbox (`interaction-math.ts`) is kept, pruned down to just the bindings parser + evaluator that `instrument` depends on
- Offscreen render + thumbnail capture is tracked separately (not part of this pass)

### Interaction (offscreen render + thumbnail, V4-B)

- **`figure.plotly` / `instrument` writes now render a real thumbnail:** after a successful write, Prism renders the figure once in a hidden window and screenshots it — the screenshot replaces the generic icon on the Chat fence card, so you can tell what an artifact looks like without opening the panel
- **Closes a silent validation gap:** file-backed figures (a `.json` resource with `role: "figure-json"`) were previously only checked for *existing on disk* — a malformed or invalid figure file surfaced no error until a human opened the panel. The same render pass now actually parses and validates that file; a failure lands in `.last-error.json` (`phase: "thumbnail"`) so the Agent can self-repair without anyone looking
- **Fully async, never blocks the write:** capture happens in the background after `interaction-write` returns; the Chat card refreshes automatically once the thumbnail lands (no manual reload). Rapid rewrites to the same artifact are single-flighted — only the latest content's thumbnail sticks, no flicker from an out-of-order capture
- No Agent-facing changes — this is a host-only capability, no new tool/prompt surface

### Interaction (`figure.script` escape hatch, V5)

- **`figure.script` (new, last resort):** when `figure.plotly`/`instrument` genuinely can't express a visualization (a molecule structure, custom non-Plotly geometry), the Agent can now write a real JS module (`export function render(ctx)`) that Prism mounts in a locked-down sandboxed iframe — no arbitrary code runs outside that sandbox
- **Hard security boundary, not a policy:** the iframe has no `allow-same-origin`, a network-denying Content-Security-Policy, and a read-only `ctx` (mount element, Plotly, optional THREE.js, declared resources, a one-time snapshot of bindings/size/theme). `import`, `eval`, `fetch`, `window.parent`, and other escape attempts are rejected at write time, before anything ever executes
- **No live re-render:** unlike `instrument`, dragging a binding slider does nothing here — bindings are a mount-time snapshot. Prism steers the Agent to `instrument` first; `figure.script` stays a deliberate one-off fallback, not a returning-to-`scene.program` shortcut
- Also gets a thumbnail via the same offscreen-render pipeline as `figure.plotly`/`instrument` (V4-B), reusing the sandbox HTML builder so the thumbnail and the live panel render identically

### Interaction (structural diagrams, V6-A)

- **`diagram.mermaid` (new):** the Agent can now write structural/flow diagrams — flowcharts, DAGs, proof trees, call graphs — as plain Mermaid or Graphviz DOT text (`model.engine: "mermaid" | "dot"`), rendered directly by the trusted library, no JSON scaffold to author
- **Not a code sandbox:** unlike `figure.script`, this kind is declarative text only — Mermaid runs with `securityLevel: "strict"` (no `click` callback bindings) and Graphviz's compiled SVG goes through a defensive sanitize pass before it's shown; links inside a diagram open in Prism's in-app browser instead of navigating away
- Static render only in this pass — no live bindings or step-through yet (that lands with `graph.network`/Cytoscape in a later phase)
- Also gets a real thumbnail via the same offscreen-render pipeline as the other kinds (V4-B)
