# Changelog — 0.6.x series

## 0.6.6 (Unreleased)

### Settings / Models

- Fix DeepSeek (and other former built-ins) coming back after Remove → restart: legacy key→provider promote runs only when the added-providers list was never written (then one-shot), and Remove clears that vendor’s API key / models / pins like OpenRouter and Zen

### Performance

- First chat send after app start: sync project agents/skills before connecting OpenCode; skip OpenCode reload when the process just spawned or a credential restart is about to happen; trim credential compare to avoid false restarts; MCP ensure/apply no longer invalidates the whole project prewarm — cuts the credential+skills double OpenCode restart on cold first message
- OpenCode startup: sync last-project experts/skills/instructions **before** the first spawn (same credential env as chat:send); stop wiping intentional skill allow/deny maps on every spawn — cold start aims for one resident process, not spawn→prewarm→reload
- Fix false credential restart on first send: `opencode-go` / `opencode-zen` share `OPENCODE_API_KEY` — stop last-wins overwrite and ignore renderer catalog `apiKey` overlays; resolve with preferred provider (`aiProvider` / current chat); log which env keys changed (lengths only) if a real restart is needed

### Chat timing

- **Worked for / Thought for** use OpenCode `time.start/end` (and sealed live clocks) instead of inventing `toolCount×0.4` or text-length guesses; reload keeps persisted durations
- Activity fold freezes when trailing answer prose starts — final reply streaming is no longer counted into Worked for
- Nested thinking timers track each thinking block (later think→tool→think segments no longer stop after the first tool)
- Fix fold header vs nested Thought time mismatch: completed activity summary prefers sealed/OpenCode duration (live freeze often started later and looked shorter); nested Thinking labels use the same i18n strings as the fold
- Fix completed turn still showing **思考中…** on the activity fold when only a short think ran (no tools / no sealed duration) — settled state always uses Thought for, not the live Thinking label

### Chat errors

- Unexpected turn failures (OpenCode/provider errors, empty turn, connection lost, turn timeout) print into the **assistant reply** like typical agent apps — raw upstream text when available; no duplicate error toast/banner (Retry stays under the failed turn)
- Task failure rewrite only covers exact opaque `Task cancelled` (and user Stop → `user_cancel`) — richer provider errors on the Task tool pass through unchanged

### Experts / Task

- P0 hardening: nested Task deny uses `parent_id` (not only late mark); Explore/General get YAML `task: deny`; nested-deny copy fixed; multi-`@Expert` follow-up deferred until open Tasks settle; Task↔child bind prefers `session.agent` / index (no multi-pending FIFO); superseded + await_timeout wired; early Stop retries child abort; **Plan mode may Task** explore/experts (still hard-denies Task→`@plan`/`@build`); custom experts auto-get nested Task deny on sync
- Settings → Models: **Subagent model** — one global default for Task / Explore / Expert subagents (same picker pattern as multimodal helper); unset inherits the main chat model; per-expert model in the editor still wins when set
- Subagent link: split clocks — muted UI hint after **12s**, orphan `parent_id` retries keep going up to **90s** (dense poll every 250ms for the first 5s); late link still attaches and clears the hint
- Link miss is soft degrade only — no longer paints a false “Task did not finish” while Explore/experts are still running; OpenCode Task success/failure remains the completion truth
- Fix false “Plan mode” cancel: a stale Task-link watchdog no longer aborts the next prompt — cleared when the parent turn ends and again when you send a new message; specific link/abandon errors are not overwritten by the opaque Plan hint
- Structured Task errors (`opencode_cancelled`, nested/reserved deny) replace opaque OpenCode “Task cancelled” for UI and persisted tool output; main agent is guided to continue after a failed Task result
- Expert Task cards: muted hint when activity stream never linked; success clears sticky errors; late `subagent_type` backfill updates `@Explore` (etc.) instead of placeholder `@expert`
- Composer `@Expert` binds this turn’s Task allowlist: main agent **must** Task each @’d id (sync wait), other Task targets denied; if none were Task’d, one automatic follow-up prompts the model to do so before the turn finishes
- Task / subagent row: two-line card with Stop; click opens a composer-width run panel above the input (shared AiBar float-panel chrome); inside it reads as a mini chat — delegation prompt as a user bubble, expert thinking/tools/reply streaming like the main session; AiBar stacks this panel over the main run panel; Stop aborts the child session and returns a cancel result to the main agent
- Fix Task run panel stuck on **Working…** / **暂无活动**: OpenCode often never forwards child `session/update` over ACP — after Task↔child link, Prism polls SQLite for the subagent’s parts and mirrors them into the run panel; also avoid treating a just-created parent session as an orphan when `session/update` races ahead of tab registration
- Built-in **paper-search-mcp** is no longer started at `session/new` (was `npx -y` eager connect on every new chat). MCP connects only when composer `@` / orchestrator / @Expert allowlist asks for it; `@Literature Synthesizer` (etc.) still pulls its declared MCP for that turn
- Paper Search is no longer locked on: Settings can disable or remove it; ensure/repair no longer force-reenables or re-adds a deleted entry (`session/new` still attaches no MCP)
- **Planned (post-P0, not shipped):** **P1** — OpenCode background Task + join (fire-and-forget, main agent continues, multi-card async); **P2** — parallel Task polish (join UX, empty-activity states, observability). Requires OpenCode binary spike before UI work.
- Task turns: while a Task is still running, interim assistant prose no longer renders as the final reply (stays in Worked for until the Task settles); avoids “answer appears → disappears when synthesis arrives”
- Task card / run panel: show a muted hint when the activity stream never linked (连接中… / 活动流未挂上) instead of a blank Working… forever; Stop before link aborts parent’s child sessions so the expert does not keep running after the UI says stopped
- Subagent panel prompt expand/collapse strings use i18n (zh/en)
- Subagent final reply streams like the main session (accumulate ACP text deltas; SQLite snapshot no longer shrinks a longer live reply)
- Reopen a historical Task run panel: hydrate thinking/tools/reply from OpenCode SQLite (was memory-only → blank 「暂无活动」)
- Stop on a Task: mark `user_cancel`, abort the child, and patch the parent Task tool output so the main agent sees a clear “user stopped” result and can continue (no longer rewritten as “not a user cancel”)
- Fix Task Stop not actually stopping the subagent: `session/cancel` was fired without await via `extNotification` (OpenCode never cancelled the child, parent Task hung). Now awaits `conn.cancel()`, resolves the linked child from the EventMapper, freezes the run-panel stream, and lets the main agent receive `user_cancel` when the Task tool completes
- Fix Task Stop leaving the main agent hung: OpenCode ACP `session/cancel` only aborts ACP-registered sessions (`session/new`), not Task child sessions — Prism now also `POST /session/:id/abort` on OpenCode’s local HTTP API (default `:4096`) so the child stops and the parent Task completes with `user_cancel` for the main agent to continue (no more wait-until-timeout)
- Task Stop is two-phase: UI shows **Stopping…** immediately (freeze child stream); **Stopped** only after the parent Task tool finishes with `user_cancel` so the main agent continues — never ACP-cancel/abort the parent turn; child abort uses HTTP control-plane only; abort/settlement failure stays honest (`abort_failed`, Stop can retry)
- Task card / run panel polish: compact shadcn ghost **Stop** text (i18n) instead of a square icon; open row without selected border frame; delegation prompt sticky at top like main chat; scroll-to-bottom FAB; trailing expert reply streams outside the activity fold while live
- Opening a finished Task panel starts at the **top** (live runs still follow the bottom); panel-chat uses a full-bleed focus scrim over the transcript (covers sticky user bubbles; soft blur) while composer + Task panel stay above — AiBar unchanged
- AiBar + Task float panels are taller (`72vh` / 720px cap, was 60vh / 600px)
- Chat + Files markdown share one reading rhythm (`leading` 1.7, matched paragraph/list gaps) so replies and `.md` preview no longer feel tight vs airy
- Subagent run panel open/close uses the same fade/slide animation as the AiBar capsule float panel
- Fix float-panel close jitter: exit animation was cancelled mid-flight (closing flag reset while the panel id was still open); hold opacity/transform end state instead of animate-in↔out class swaps; main panel un-peeks smoothly under a closing Task panel
- Click outside (workspace / composer / anywhere but the float panel) dismisses the Task run panel, then the main AiBar run panel — panel-chat host included
